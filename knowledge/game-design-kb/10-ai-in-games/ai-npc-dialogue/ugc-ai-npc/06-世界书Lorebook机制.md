## 核心观点

1. 世界书 = "让AI在对的时机说对的话"的引擎——不是把所有信息塞进人设，而是"提到什么话题才注入什么知识"
2. 解决了AI角色的核心矛盾：信息量大（丰富人设）vs Token有限（推理成本）→按需加载
3. 经过3年开源社区迭代，是业界最成熟的"AI角色定义标准"
4. 核心价值：节省Token + 信息精准 + AI不被无关信息干扰 + 动态人设变化

## 关键方法论/框架

### 世界书6层触发机制

| 层级 | 机制 | 作用 | 和平精英适配 |
|------|------|------|-------------|
| 1 | **关键词触发** | 对话提到X→注入关于X的知识 | 口头禅/AI对武器/地图的反应 |
| 2 | **概率触发** | 8%概率冒出随机想法 | AI偶尔说"题外话"=活人感 |
| 3 | **粘滞（Sticky）** | 情绪触发后持续N轮 | 决赛圈紧张状态持续到结算 |
| 4 | **冷却（Cooldown）** | 同一话题N轮内不重复 | 避免AI像复读机 |
| 5 | **条件组合** | "决赛圈+紧张"才触发认真模式 | 场景化性格切换 |
| 6 | **分组竞争** | 随机从候选池中选一条 | 每次上线欢迎词不一样 |

### 数据结构（条目级）

| 字段 | 作用 | 设计启示 |
|------|------|----------|
| Key（关键词） | 匹配用户/AI消息中的词→触发注入 | 玩家设定的"AI对什么话题有反应" |
| Content（内容） | 触发后注入到Prompt中的文本 | 人设片段/知识/情绪状态 |
| Scan Depth | 扫描最近N条消息 | 控制响应灵敏度 |
| Token Budget | 单条最大Token数 | 控制成本 |
| Priority | 冲突时哪条优先 | 核心人设>临时状态 |
| Sticky | 触发后持续N轮 | 情绪/状态持续性 |
| Cooldown | 触发后N轮内不再触发 | 防重复 |
| Probability | 触发概率（0-100%） | 随机感=活人感 |
| Group | 同组中随机选一条 | 同一场景多种表现 |

### 和平精英的设计启示

```
用户界面（简单）：
  玩家填口头禅/选战斗偏好/写背景故事
        ↓
底层实现（世界书逻辑）：
  口头禅 → 关键词触发条目（Sticky=3轮，Cooldown=10轮）
  战斗偏好 → 对局状态触发条目（条件组合：枪声+近距离→冲锋模式）
  背景故事 → 高概率触发条目（特定话题关键词→注入回忆内容）
```

## 设计检查清单

- [ ] 人设信息是否实现了"按需加载"而非全量注入
- [ ] 是否设计了"粘滞"机制（情绪/状态不会一轮就消失）
- [ ] 是否设计了"冷却"机制（同一内容不会反复触发）
- [ ] 是否有概率触发（AI偶尔说"出乎意料"的话=活人感）
- [ ] 用户界面是否足够简单（用户不需要知道底层是世界书）

## 个人思考

- 世界书是"让有限Token产出丰富人设表现"的最优解——和平精英的AI NPC人设系统底层应该采用类似机制
- 用户永远不需要知道"世界书"这个概念——他们只需要填口头禅/选标签/写背景，系统自动转换为世界书条目
- 对创作者工具设计的启示：创作者设定"触发词→反应"的表单 = 简化版的世界书编辑器

## 核心观点

1. **好的UX是隐形的** — 玩家注意到UX时，说明UX出了问题
2. **减少认知负荷是第一原则** — 每增加一个UI元素，都是在消耗玩家的注意力预算
3. **新手引导的本质是"分阶段释放复杂度"** — 不是教所有东西，是在对的时间教对的东西
4. **HUD是游戏性格的延伸** — 侵略性HUD(鬼泣)vs极简HUD(魂系)，风格必须匹配

## 关键方法论/框架

### 框架一：游戏UX四层模型

| 层级 | 内容 | 设计目标 |
|------|------|---------|
| **信息架构** | 菜单结构、页面层级、导航逻辑 | 玩家3步内找到任何功能 |
| **HUD设计** | 战斗信息、状态显示、小地图 | 关键信息一眼可读 |
| **操作映射** | 按键布局、手势设计、快捷操作 | 操作直觉化，减少学习成本 |
| **新手引导** | 教学流程、提示系统、难度曲线 | 渐进式释放复杂度 |

### 框架二：新手引导四原则

1. **Show, Don't Tell**: 用互动教学替代文字弹窗
2. **Just-in-Time**: 在玩家即将需要时才教（而非一次性灌输）
3. **Safe-to-Fail**: 教学环境允许失败且无惩罚
4. **Layered Complexity**: 复杂度分层释放（如每10级解锁新系统）

### 框架三：HUD信息优先级

| 优先级 | 信息类型 | 显示方式 | 案例 |
|--------|---------|---------|------|
| P0 核心 | 血量/弹药/技能CD | 常驻显示 | 所有游戏 |
| P1 重要 | 小地图/队友状态 | 半透明常驻 | FPS/MOBA |
| P2 参考 | 得分/击杀数 | 角落/渐隐 | 竞技类 |
| P3 辅助 | 任务提示/系统通知 | 触发式/临时 | RPG |

### 框架四：尼尔森启发式在游戏中的应用

| 启发式原则 | 游戏应用 |
|-----------|---------|
| 系统状态可见性 | 加载进度、技能冷却倒计时 |
| 系统与现实匹配 | 背包=物品管理、商店=购买 |
| 用户控制与自由 | 暂停/撤销/重试/跳过剧情 |
| 一致性与标准 | 同类操作统一交互方式 |
| 错误预防 | 珍贵道具出售前二次确认 |
| 识别而非回忆 | 技能图标直观、道具标签 |

## 设计检查清单

- [ ] **3步可达**: 任何核心功能是否3步内可触达？
- [ ] **信息分级**: HUD是否按P0-P3分了优先级？
- [ ] **新手引导时机**: 是否在"玩家需要时"才教学？
- [ ] **操作直觉**: 核心操作是否不需要看教程？
- [ ] **二次确认**: 不可逆操作（出售/删除）是否有确认？
- [ ] **可跳过**: 剧情/教程是否可跳过？

## GDD三层文档体系

| 文档 | 目标受众 | 篇幅 | 内容 |
|------|---------|------|------|
| **概念文档** | 决策层/投资人 | 3-5页 | 愿景·核心体验·差异化·市场定位 |
| **GDD主文档** | 全团队 | 30-100页 | 所有系统的完整设计说明 |
| **技术设计文档(TDD)** | 程序团队 | 按系统拆分 | 逻辑细节·接口定义·数据结构 |

## GDD主文档标准目录

```
1. 游戏概述
   1.1 一句话描述
   1.2 核心体验（30秒/3分钟描述）
   1.3 目标受众
   1.4 参考作品与差异化

2. 核心机制
   2.1 核心循环图
   2.2 主要系统列表与关系图
   2.3 每个系统的概述

3. 详细系统设计（每个系统一章）
   3.X.1 功能概述
   3.X.2 详细规则
   3.X.3 UI/交互流程
   3.X.4 数值参数
   3.X.5 异常处理
   3.X.6 与其他系统的关联

4. 内容规划
   4.1 关卡/地图列表
   4.2 角色/敌人列表
   4.3 道具/装备列表

5. 技术需求
   5.1 平台与性能目标
   5.2 网络方案
   5.3 第三方SDK

6. 排期与里程碑

7. 版本历史
```

## 设计检查清单

- [ ] 是否有"一句话描述"能概括整个游戏？
- [ ] 核心循环图是否清晰？
- [ ] 每个系统是否都有"异常处理"章节？
- [ ] 版本历史是否持续更新？

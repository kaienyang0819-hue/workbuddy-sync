# 需求文档写作：从模糊到精确

> **核心观点**：策划最大的沟通成本来自"需求描述不精确"。用"输入→处理→输出"的程序思维写需求，加上状态机描述和边界条件，可以消除90%的理解歧义。

## 方法论

### 精确需求描述四要素
1. **触发条件**：什么情况下触发这个功能？（When）
2. **输入参数**：需要哪些数据/玩家操作？（Input）
3. **处理逻辑**：怎么计算/判断？（Process）
4. **输出结果**：玩家看到/得到什么？（Output）

### 状态机描述法
- 适用于角色状态/系统流程/UI状态
- 明确列出：所有状态+转换条件+转换动作
- 用状态转换图可视化，比文字描述更清晰

### 消除歧义的技巧
- **具体数值代替形容词**："伤害较高"→"伤害150点"
- **穷举代替概括**："各种情况"→列出所有情况
- **反例验证**：写完需求后想"如果不是这样呢？"
- **边界先行**：先写边界条件再写正常流程

### 需求变更管理
- 变更必须标注：变更内容+变更原因+影响范围+变更日期
- 用颜色/删除线标记修改痕迹
- 重大变更需要评审确认

## 检查清单
- [ ] 每条规则是否有触发→输入→处理→输出？
- [ ] 复杂流程是否用状态机描述？
- [ ] 是否消除了所有形容词模糊描述？
- [ ] 变更是否有标注和追溯？

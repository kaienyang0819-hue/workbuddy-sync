# 版本更新公告写作指南

## 核心观点
版本更新公告不是简单的patch notes罗列，而是与玩家沟通的重要触点。好的公告能提升玩家期待、缓解争议、建立信任；差的公告则引发社区暴动。

## 方法论

### 公告类型金字塔
1. **大版本公告**：新赛季/新地图/新英雄，需要完整的营销包装
2. **常规更新公告**：平衡调整/BUG修复，需要清晰准确
3. **热修复公告**：紧急修复，需要快速透明
4. **运营活动公告**：限时活动/福利，需要吸引力

### 写作框架STAR
- **S(Summary)**：一句话概括本次更新的核心亮点
- **T(Timeline)**：明确更新时间、停服时间、补偿方案
- **A(Action)**：详细列出每项改动，分类清晰
- **R(Reason)**：对争议改动解释设计意图（关键！）

### 平衡调整公告的黄金法则
1. **先说WHY再说WHAT**：为什么削弱这个英雄，数据表现如何
2. **量化描述**：伤害从100→85（-15%），不要只说"略微降低"
3. **承认问题**：如果是修BUG导致的平衡问题，坦诚说明
4. **展望未来**：告诉玩家接下来的调整方向

### 反面教材
- 模糊描述："优化了部分体验" → 玩家完全不知道改了什么
- 遗漏改动：暗改数值不写进公告 → 信任崩塌
- 过度营销：把BUG修复包装成"重大更新" → 适得其反

## 案例
- **英雄联盟Patch Notes**：业界标杆，每个英雄改动都有设计师备注
- **原神版本前瞻直播**：用直播形式做版本公告，结合福利码互动
- **暴雪"蓝贴"文化**：通过论坛回复解释设计意图，建立社区信任

## 检查清单
- [ ] 是否有一句话总结本次更新核心
- [ ] 停服/维护时间是否明确
- [ ] 所有改动是否分类列出
- [ ] 争议改动是否解释了原因
- [ ] 数值改动是否量化表述
- [ ] 是否有已知问题说明
- [ ] 语气是否与游戏调性一致

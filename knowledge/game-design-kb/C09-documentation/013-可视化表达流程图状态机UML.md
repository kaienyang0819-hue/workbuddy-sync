# 可视化表达：流程图/状态机/UML

## 核心观点
"一张图胜过千言万语"在策划文档中格外适用。复杂的系统逻辑用文字描述容易遗漏，用可视化工具表达则直观、准确、便于评审。策划不需要精通UML，但必须掌握3种核心图表。

## 方法论

### 策划必备三图
1. **流程图（Flowchart）**：描述玩家操作流程、功能触发逻辑
2. **状态机图（State Diagram）**：描述对象状态转换（角色/任务/道具状态）
3. **时序图（Sequence Diagram）**：描述多系统/多角色的交互时序

### 流程图最佳实践
- **起始/结束**：圆角矩形
- **操作步骤**：矩形
- **判断分支**：菱形（条件写在箭头上）
- **并行处理**：粗横线
- **核心原则**：从左到右/从上到下，主流程居中，异常分支靠边

### 状态机设计规范
```
[初始状态] --触发条件/动作--> [目标状态]
```
- 每个状态必须有进入条件和退出条件
- 标注状态内行为（Entry/Do/Exit）
- 终态必须可达（避免死循环/孤立状态）
- 常见陷阱：忘记处理"取消""超时""异常中断"

### 工具推荐
| 工具 | 适用场景 | 优势 |
|------|----------|------|
| draw.io | 流程图/状态机 | 免费、支持协作、导出方便 |
| Mermaid | 嵌入文档的图表 | 纯文本定义、版本可控 |
| PlantUML | 时序图/类图 | 代码驱动、CI/CD集成 |
| Figma | 高保真交互流程 | 与UI设计无缝衔接 |
| XMind | 脑暴/信息架构 | 快速发散、整理思路 |

### 图表规范
- 标题：必须有，说明这张图描述什么
- 图例：颜色/形状含义要标注
- 版本号：随文档更新同步
- 层级：复杂系统先画总览图，再画子流程详图

## 案例
- **MOBA匹配流程**：从点击匹配→队列→匹配算法→确认→进入选人→加载→开始，完整状态机
- **任务系统状态机**：未接取→已接取→进行中→待提交→已完成/已放弃，每个状态转换都有触发条件

## 检查清单
- [ ] 复杂逻辑是否用图表辅助说明
- [ ] 图表是否有标题和图例
- [ ] 状态机是否覆盖所有异常状态
- [ ] 流程图是否有明确的起止点
- [ ] 图表与文字描述是否一致

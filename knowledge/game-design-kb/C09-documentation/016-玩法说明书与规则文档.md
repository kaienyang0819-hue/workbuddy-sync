# 玩法说明书与规则文档

## 核心观点
玩法说明书是连接策划与开发团队的"契约"。它不是给玩家看的说明书，而是让程序、美术、QA都能准确理解"这个玩法到底怎么运作"的技术规格文档。

## 方法论

### 玩法文档五要素
1. **目标（Goal）**：这个玩法要给玩家什么体验？
2. **规则（Rules）**：玩法的核心机制和限制条件
3. **流程（Flow）**：从进入到结束的完整时序
4. **数据（Data）**：所有可配置的数值参数
5. **边界（Edge Cases）**：异常情况处理

### 规则描述的MECE原则
- **M(Mutually Exclusive)**：每条规则不能互相矛盾
- **E(Collectively Exhaustive)**：所有情况都要覆盖，不能有"未定义行为"
- 用"如果…则…否则…"的格式，让逻辑无二义性

### 规则优先级
当多条规则冲突时，必须定义优先级：
```
1. 安全规则（防作弊） > 2. 核心玩法规则 > 3. 辅助功能规则
示例：无敌状态下被击退 → 不受伤但位移生效（安全>伤害，但位移独立）
```

### 版本管理
- 每次修改标注：改了什么、为什么改、影响范围
- 重大规则变更需要重新评审
- 保留历史版本，方便追溯"为什么当初这么设计"

## 案例
- **卡牌游戏综合规则文档**（如MTG/游戏王）：业界最严谨的规则文档范本
- **自走棋战斗流程文档**：回合开始→选人→战斗→结算→商店，每一步都有明确定义

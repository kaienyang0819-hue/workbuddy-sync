# 跨部门协作文档对齐方法

## 核心观点
策划文档的最终目标是让所有相关方（程序/美术/QA/运营）达成一致理解。90%的项目延期不是能力不足，而是信息不对齐。跨部门协作的核心是"对齐成本最小化"。

## 方法论

### 信息对齐四层模型
1. **目标层**：我们为什么做这个？（制作人/产品经理对齐）
2. **方案层**：具体怎么实现？（策划↔程序/美术对齐）
3. **排期层**：什么时候做完？（PM/项目经理对齐）
4. **验收层**：怎么算合格？（QA/测试对齐）

### 文档分层交付
| 受众 | 文档类型 | 核心内容 | 篇幅 |
|------|----------|----------|------|
| 制作人 | 一页纸提案 | 核心体验+ROI | 1页 |
| 程序 | 技术需求文档 | 接口定义+状态机+数据结构 | 详尽 |
| 美术 | 美术需求单 | 参考图+规格+风格说明 | 图为主 |
| QA | 测试用例文档 | 功能点+边界+预期结果 | 表格 |
| 运营 | 功能说明简报 | 玩法概述+FAQ+话术 | 简洁 |

### 评审会议最佳实践
- **会前**：提前24小时发文档，标注需讨论的问题
- **会中**：限时60分钟，记录所有决策和待办
- **会后**：24小时内更新文档并同步，标注变更点
- **跟踪**：用TAPD/Jira记录每个待办项的负责人和Deadline

### 常见对齐失败模式
- **口头约定不落文档**：3天后各方记忆不同
- **文档更新不同步**：程序看的是上周的版本
- **跨层级对齐**：策划跟程序对齐了但没跟美术说
- **假设不一致**：策划以为分辨率是1080p，美术按4K做

## 检查清单
- [ ] 所有相关方是否都拿到了最新版文档
- [ ] 评审会议决策是否已落到文档
- [ ] 待办事项是否有负责人和Deadline
- [ ] 关键假设是否显式写在文档中

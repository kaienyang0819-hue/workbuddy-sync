# SQL基础：策划必备数据查询能力

## 核心观点
不会SQL的策划只能等数据分析师排期。掌握基础SQL，策划可以自己跑数据验证假设、监控指标、定位问题。这是数据驱动设计的"最后一公里"能力。

## 方法论

### 策划常用SQL操作
```sql
-- 1. 查看某天DAU
SELECT COUNT(DISTINCT player_id) as dau
FROM login_log
WHERE date = '2026-04-03';

-- 2. 查看各等级段玩家分布
SELECT level_range, COUNT(*) as player_count
FROM (
  SELECT CASE 
    WHEN level BETWEEN 1 AND 10 THEN '1-10'
    WHEN level BETWEEN 11 AND 30 THEN '11-30'
    WHEN level BETWEEN 31 AND 60 THEN '31-60'
    ELSE '60+'
  END as level_range
  FROM player_info
) t
GROUP BY level_range ORDER BY level_range;

-- 3. 计算次日留存率
SELECT 
  a.reg_date,
  COUNT(DISTINCT a.player_id) as new_users,
  COUNT(DISTINCT b.player_id) as retained,
  ROUND(COUNT(DISTINCT b.player_id)*100.0/COUNT(DISTINCT a.player_id), 2) as retention_rate
FROM new_users a
LEFT JOIN login_log b ON a.player_id = b.player_id 
  AND b.date = DATE_ADD(a.reg_date, INTERVAL 1 DAY)
GROUP BY a.reg_date;

-- 4. 查看付费Top100玩家
SELECT player_id, SUM(amount) as total_pay
FROM payment_log
WHERE date >= '2026-03-01'
GROUP BY player_id
ORDER BY total_pay DESC
LIMIT 100;
```

### 策划SQL四件套
1. **SELECT + WHERE**：查询特定条件的数据
2. **GROUP BY + 聚合函数**：分组统计（COUNT/SUM/AVG）
3. **JOIN**：关联多张表（用户表+行为表+付费表）
4. **子查询**：复杂条件的嵌套查询

### 性能注意事项
- 大表查询加WHERE时间范围限制
- 避免SELECT *，只查需要的字段
- 先COUNT确认数据量，再拉明细
- 复杂查询先在测试环境跑

# LLM在游戏数据分析中的应用

## 核心观点
LLM正在改变游戏数据分析的工作方式：从"策划提需求→分析师跑数据→等3天"到"策划用自然语言直接查询数据"。AI不替代数据思维，但极大地降低了数据获取的门槛。

## 方法论

### LLM赋能数据分析的四大场景
1. **自然语言转SQL**："帮我查昨天各服务器的DAU和付费率"→自动生成SQL
2. **自动数据解读**：给LLM一组数据，让它自动生成分析报告
3. **舆情分析**：自动收集+分析社区评论/差评/反馈
4. **异常检测**：描述数据异常，AI辅助排查原因

### Text-to-SQL实践
```
用户输入: "过去7天每天的新增用户数和次日留存率"

LLM生成:
SELECT 
  reg_date,
  COUNT(DISTINCT new.player_id) as new_users,
  ROUND(COUNT(DISTINCT ret.player_id)*100.0/COUNT(DISTINCT new.player_id), 2) as day1_retention
FROM new_users new
LEFT JOIN login_log ret ON new.player_id = ret.player_id 
  AND ret.date = DATE_ADD(new.reg_date, INTERVAL 1 DAY)
WHERE new.reg_date >= DATE_SUB(CURDATE(), INTERVAL 7 DAY)
GROUP BY reg_date ORDER BY reg_date;
```

### AI数据报告自动化
1. 定时拉取核心指标数据
2. 喂给LLM生成分析文本
3. 自动检测异常并高亮
4. 推送到企微/飞书/钉钉

### 舆情分析Pipeline
```
数据采集(NGA/TapTap/Reddit) → 清洗去重 → LLM情感分类 
→ 主题聚类 → 热点提取 → 周报自动生成
```

### 注意事项
- **幻觉风险**：AI生成的SQL必须人工检查再执行
- **数据安全**：敏感数据不能直接给外部LLM
- **能力边界**：复杂分析仍需专业分析师

## 案例
- **绝区零LLM舆情分析**：用大模型自动分析TapTap评论，发现核心不满主题
- **某大厂Text-to-SQL**：策划自助查数平台，减少60%数据需求排期

# 需求优先级排序方法论

## 核心观点
永远有做不完的需求。策划的核心能力之一是"决定不做什么"。科学的优先级排序帮助团队把有限的资源投入到产出最大的功能上。

## 方法论

### RICE评分法
| 因素 | 定义 | 评分方式 |
|------|------|----------|
| **R**each（覆盖度） | 影响多少玩家 | 人数/百分比 |
| **I**mpact（影响力） | 对体验的影响程度 | 3=大/2=中/1=小/0.5=极小 |
| **C**onfidence（信心度） | 估算的可靠性 | 100%/80%/50% |
| **E**ffort（工作量） | 需要多少人天 | 人天数 |

**RICE分数 = (R × I × C) / E**

### MoSCoW方法
- **Must have**：没有就不能上线
- **Should have**：强烈期望有，但缺了能凑合
- **Could have**：有更好，锦上添花
- **Won't have**：本期不做（但记录下来）

### 游戏需求优先级四象限
```
           紧急
    ┌──────┬──────┐
    │ 救火 │ 核心 │
    │(BUG) │(版本) │
不重要├──────┼──────┤重要
    │ 放弃 │ 排期 │
    │(nice)│(优化) │
    └──────┴──────┘
           不紧急
```

### 需求backlog管理
1. **周度梳理**：每周review backlog，清理过时需求
2. **故事点估算**：用扑克牌估算（1/2/3/5/8/13/21）
3. **依赖关系**：标注需求间的前置依赖
4. **技术债专项**：每个Sprint预留20%容量处理技术债

### 说"不"的技巧
- 不是"不做"，是"不在本期做"
- 用数据说话："做A的ROI是B的3倍，建议优先A"
- 提供替代方案："完整版需要3周，简化版1周能达到80%效果"

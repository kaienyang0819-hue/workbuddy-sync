# 外包管理与质量控制

## 核心观点
现代游戏开发大量依赖外包（美术/音频/本地化/QA）。管理外包不是"甩需求等交付"，而是需要一套完整的质量控制体系。外包质量=需求清晰度×过程管理×验收标准。

## 方法论

### 外包管理全流程
```
需求准备 → 供应商评估 → 合同签订 → Kick-off → 
过程管控 → 里程碑验收 → 最终交付 → 复盘评估
```

### 需求文档要求（给外包的文档要更详细）
- **参考图/参考物**：必须有，文字描述歧义大
- **规格参数**：精确到像素/面数/帧率/文件格式
- **风格指南**：色板/材质/比例/禁忌
- **验收标准**：量化的通过/不通过条件
- **修改次数**：合同约定免费修改次数

### 质量控制三道关
1. **初稿审查**（30%进度）：方向是否正确
2. **中期审查**（60%进度）：品质是否达标
3. **终审交付**（100%进度）：按验收标准逐项检查

### 常见问题与对策
| 问题 | 对策 |
|------|------|
| 风格不统一 | 提供Style Guide + 前3个做完后统一审标 |
| 进度延期 | 里程碑拆细 + Buffer预留20% |
| 品质不达标 | 明确验收标准 + 修改次数限制 |
| 沟通成本高 | 指定单一对接人 + 周报机制 |

## 检查清单
- [ ] 外包需求文档是否足够详细
- [ ] 验收标准是否量化
- [ ] 是否有里程碑检查点
- [ ] 合同是否约定修改和延期条款

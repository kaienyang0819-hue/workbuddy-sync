# 工时估算与排期技巧

## 核心观点
"这个需求要多久？"——策划最害怕也最需要回答的问题。估不准导致要么承诺过多疯狂加班，要么过度保守浪费资源。掌握科学的估算方法，让排期从"猜"变成"算"。

## 方法论

### 估算方法对比
| 方法 | 精度 | 适用阶段 | 耗时 |
|------|------|----------|------|
| T恤尺码(S/M/L/XL) | 低 | 早期规划 | 5分钟 |
| 故事点(Story Points) | 中 | Sprint规划 | 30分钟 |
| 人天估算 | 中高 | 详细排期 | 1小时 |
| 三点估算(PERT) | 高 | 关键路径 | 1小时+ |

### 三点估算法(PERT)
```
预期工时 = (乐观 + 4×最可能 + 悲观) / 6

示例：角色技能系统开发
乐观: 10天 / 最可能: 15天 / 悲观: 30天
预期 = (10 + 4×15 + 30) / 6 = 16.7天 ≈ 17天
```

### 排期黄金法则
1. **加Buffer**：在估算基础上加20-30%缓冲
2. **拆任务**：单个任务不超过3天，超过就继续拆分
3. **标依赖**：明确哪些任务可以并行，哪些必须串行
4. **留联调**：策划+程序+美术联调时间通常占开发时间的30%
5. **留测试**：QA测试+修BUG时间约占开发的40%

### 常见估算陷阱
- **过度乐观**：只估核心功能，忘了边界处理和联调
- **锚定效应**：老板说"应该3天能搞定"，你就不敢说5天
- **忽视切换成本**：一个人同时做3个需求，效率不是1/3而是1/4

### Velocity（速率）
- 跟踪团队每个Sprint完成的故事点数
- 3个Sprint后趋于稳定，可以用来预测未来产能
- 不要用Velocity比较不同团队，只用于同一团队自我预测

## 检查清单
- [ ] 是否用了结构化的估算方法
- [ ] 是否预留了Buffer和联调/测试时间
- [ ] 任务是否拆分到3天以内
- [ ] 依赖关系是否标注清楚

## 核心观点

1. **策划的每个设计决策都有性能成本** — 多10个敌人/多一层特效/多一个系统都不是免费的
2. **性能预算是与程序协商的结果** — 不是"能不能做"而是"在预算内能做多少"

## 关键约束与预算参考

### 同屏对象数预算（手机/PC）

| 对象类型 | 手机(骁龙8系) | PC(RTX3060+) |
|---------|-------------|-------------|
| 同屏角色 | 20-30 | 50-100 |
| 同屏特效 | 50-80粒子系统 | 200+ |
| Draw Call | 200-400 | 2000-4000 |
| 三角面 | 50-100万 | 500万+ |

### 策划常踩的性能雷区

| 雷区 | 后果 | 正确做法 |
|------|------|---------|
| 大量同屏敌人 | 帧率暴跌 | 与程序确认预算再设计 |
| 全局实时光影 | GPU爆炸 | 关键区域实时+其他烘焙 |
| 无限制粒子特效 | 卡顿 | 特效LOD+超出预算自动消隐 |
| 巨大开放世界无分区 | 内存溢出 | 流式加载+分区管理 |
| 大量UI动效同时播放 | CPU占用高 | UI动效预算+优先级 |

### 策划性能沟通模板

```
功能: XXX系统
性能需求:
  - 同屏最大敌人数: ?
  - 每个敌人特效数: ?
  - 战斗场景总Draw Call预算: ?
  - 加载时间要求: <3秒
  - 目标帧率: 60fps/30fps
请程序评估是否可行，如超预算建议降级方案。
```

## 设计检查清单

- [ ] 设计方案是否标注了性能需求（同屏数/特效数）？
- [ ] 是否与程序确认了性能预算？
- [ ] 超预算时是否准备了降级方案（减少同屏/简化特效）？
- [ ] 开放世界是否设计了流式加载方案？

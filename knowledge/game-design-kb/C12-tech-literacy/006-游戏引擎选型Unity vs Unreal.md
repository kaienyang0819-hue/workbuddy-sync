## 核心观点

引擎选择直接决定了项目的技术上限、开发效率和人才储备。策划不需要精通引擎代码，但必须理解两大引擎的能力边界和设计约束。

### 双引擎全维度对比

| 维度 | Unity | Unreal Engine |
|------|-------|---------------|
| **语言** | C# | C++ / Blueprint |
| **渲染上限** | 中高（URP/HDRP） | 顶级（Nanite/Lumen） |
| **手游适配** | 极强（生态成熟） | 中等（优化门槛高） |
| **学习曲线** | 平缓 | 陡峭 |
| **开源程度** | 部分开源 | 完整源码 |
| **编辑器扩展** | 灵活（C#工具链） | 强大（蓝图+编辑器SDK） |
| **多人网络** | 需自建/第三方 | 内置Replication |
| **版税** | 免费→分成 | 免费→5%（100万后） |
| **典型品类** | 手游/独立/2D/轻3D | 3A/主机/开放世界 |

### UE5核心技术（策划需知）
- **Nanite**：虚拟几何体，无需手动LOD，意味着场景可放置海量高精度物件
- **Lumen**：全局光照，无需烘焙光照贴图，动态光照自由调整
- **World Partition**：大世界流式加载，支持开放世界设计
- **MetaHuman**：照片级数字人，适合叙事驱动项目
- **Control Rig**：运行时动画控制，实现程序化动画

### Unity优势场景
- **DOTS/ECS**：面向数据的技术栈，支撑大规模实体（万人同屏）
- **Addressables**：灵活资源管理，热更新友好
- **跨平台**：一次开发25+平台部署
- **2D Toolkit**：Tilemap/Sprite/动画状态机完整工具链

## 方法论

### 策划选型参考矩阵
```
手游 + 轻量级 → Unity首选
主机3A + 写实画面 → UE5首选
开放世界 + 大地图 → UE5（World Partition）
2D/像素 + 独立游戏 → Unity / Godot
VR/AR → 两者均可（Unity生态更成熟）
MMO + 海量实体 → Unity DOTS / 自研引擎
```

### 策划与引擎能力的对话
1. **知道能力边界**：不提超出引擎能力的需求
2. **理解性能预算**：DrawCall、Triangle、内存的概念
3. **善用编辑器**：策划应能使用编辑器调数值、测试关卡
4. **理解管线**：资源从美术到引擎的完整流程

## 案例分析

| 游戏 | 引擎 | 选型原因 |
|------|------|----------|
| 原神 | Unity(深度定制) | 多平台+手游优先+团队技术栈 |
| 黑神话悟空 | UE5 | 极致画面+Nanite+Lumen |

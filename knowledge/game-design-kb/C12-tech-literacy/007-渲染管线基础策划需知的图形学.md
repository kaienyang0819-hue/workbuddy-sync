## 核心观点

游戏画面的每一帧都经历一条完整的"渲染管线"。策划理解这条管线，才能提出合理的美术需求、预估性能开销、与程序/美术有效沟通。

### 渲染管线简化流程
```
CPU阶段：场景裁剪→排序→提交DrawCall
    ↓
GPU阶段：顶点着色→光栅化→片元着色→后处理
    ↓
输出：最终画面（帧缓冲→屏幕）
```

### 策划必知的核心概念

| 概念 | 含义 | 策划影响 |
|------|------|----------|
| **DrawCall** | CPU向GPU发送一次渲染指令 | 数量太多会卡CPU→场景物件数有上限 |
| **Triangle Count** | 三角面数 | 角色/场景面数预算直接影响美术精度 |
| **LOD** | Level of Detail | 远处物体自动降精度→影响远景设计 |
| **Overdraw** | 同一像素被重复绘制 | 半透明粒子多=性能杀手→特效需克制 |
| **Batch** | 合批（合并DrawCall） | 相同材质物件可合批→场景设计需考虑 |
| **Shader** | 着色器程序 | 决定材质表现力→特殊效果需提前沟通 |
| **后处理** | Bloom/DOF/TAA等 | 画面风格化手段→但有性能开销 |

### 性能预算思维

**手游60fps预算参考**：
- 每帧时间：≤16.6ms
- DrawCall：≤300-500
- 三角面：≤50万-100万
- 内存：≤1.5GB（中端机）
- 粒子数：≤500同屏

**PC/主机预算**：
- 预算宽裕5-10倍，但也需控制

## 方法论

### 策划的性能敏感度培养
1. **提需求前先问预算**："这个效果大概多少DrawCall？"
2. **理解优先级**：主角>队友>敌人>NPC>环境
3. **替代方案思维**：实时光影→烘焙光照，3D粒子→Flipbook，实时反射→SSR
4. **移动端思维**：手游策划尤其需要"预算思维"

### 与技术美术的沟通模板
```
策划诉求：我希望BOSS登场时有一个全屏光效爆发
技术翻译：这需要几个全屏后处理Pass + 大量半透明粒子
性能评估：在中端手机上可能掉帧5-10fps
折中方案：用预渲染序列帧 + 局部Bloom实现80%效果
```

## 案例分析

| 游戏 | 渲染特点 | 策划启示 |
|------|----------|----------|
| 原神 | 卡通渲染+后处理 | NPR风格降低模型精度要求 |
| 黑神话悟空 | Nanite+Lumen | 写实无LOD→场景设计自由度极高 |
| 塞尔达TotK | 风格化低面数 | 证明画面品质≠多边形数量 |
| 永劫无间 | PBR+特效大量 | 特效是表现力核心但需严控预算 |

## 核心观点

版本控制是团队协作的基础设施。策划每天提交配置表、文档，都在使用版本控制。理解核心概念能避免"覆盖同事改动""找不回旧版本"等灾难。

### SVN vs Git对比
| 维度 | SVN | Git |
|------|-----|-----|
| 架构 | 中心式 | 分布式 |
| 离线工作 | 不可 | 可以 |
| 分支成本 | 高 | 极低 |
| 学习曲线 | 平缓 | 陡峭 |
| 游戏行业 | 仍广泛使用 | 越来越主流 |
| 大文件 | 原生支持 | 需Git LFS |

### 策划必会操作
- **Update/Pull**：拉取最新→开工前必做
- **Commit/Push**：提交改动→写清楚改了什么
- **Revert**：回滚错误修改
- **Diff**：对比两个版本差异
- **Resolve Conflict**：解决配置表冲突

### 配置表冲突预防
1. **锁定机制**：SVN Lock，编辑前锁文件
2. **分表策略**：不同策划负责不同Sheet
3. **及时提交**：小步提交，避免大冲突
4. **沟通先行**：要改公共表先在群里说一声

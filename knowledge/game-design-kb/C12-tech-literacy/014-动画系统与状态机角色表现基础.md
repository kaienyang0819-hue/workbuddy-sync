## 核心观点

动画系统决定了角色"看起来怎么动"。策划需理解动画状态机和混合树，才能提出合理的动作需求和连招设计。

### 核心概念
| 概念 | 含义 | 策划应用 |
|------|------|----------|
| **Animation Clip** | 单个动画片段 | 待机/跑步/攻击 |
| **State Machine** | 状态机 | 定义动画切换逻辑 |
| **Blend Tree** | 混合树 | 走跑之间平滑过渡 |
| **Transition** | 过渡条件 | 何时从A动画切到B |
| **IK** | 反向动力学 | 脚踩地面/手持武器适配 |
| **Root Motion** | 根运动 | 动画驱动位移（格斗/动作游戏常用） |
| **Animation Event** | 动画事件 | 在特定帧触发逻辑（出招判定帧） |
| **Montage** | 蒙太奇（UE） | 可打断/组合的动画序列 |

### 策划动作设计关键帧
```
攻击动画时间线：
├─ 前摇(Startup)：按下攻击→判定生效前的等待
├─ 判定帧(Active)：实际产生伤害的窗口
├─ 后摇(Recovery)：判定结束→可输入下一指令的等待
└─ 取消窗口(Cancel)：可被特定操作打断的时间段
```

### 策划需注意的技术约束
1. **动画数量=内存开销**：每个角色的动画越多，资源占用越大
2. **混合≠万能**：相差太大的动画混合会"骨折"
3. **Root Motion vs 程序控制**：两种移动方式各有适用场景
4. **网络同步**：其他玩家看到的动画可能有延迟/简化

## 核心观点

外挂和作弊是竞技游戏的头号公敌。策划在设计系统时就应具备"安全意识"，从设计层面降低被利用的风险。

### 常见作弊类型
| 类型 | 手段 | 策划影响 |
|------|------|----------|
| **修改内存** | 改金币/血量 | 关键数据必须服务端存储 |
| **加速器** | 修改游戏速度 | 时间相关逻辑服务端校验 |
| **透视/自瞄** | 读取内存数据 | 视野外信息不发给客户端 |
| **协议篡改** | 伪造请求 | 服务端校验所有操作合法性 |
| **脚本/宏** | 自动操作 | 设计需要人类判断的操作 |

### 策划防御设计原则
1. **服务端权威**：所有关键结算在服务端，客户端只做表现
2. **最小信息原则**：只发送客户端需要的数据（如FPS不发送墙后敌人位置）
3. **合理性校验**：移动速度/攻击频率超阈值判定异常
4. **经济系统保护**：物品交易/货币变动全部服务端处理
5. **行为检测**：统计玩家行为模式，异常自动标记

### 策划系统设计的安全自查
- 这个数值计算可以在客户端做吗？→ 尽量不
- 抽卡结果在哪里生成？→ 必须服务端
- 排行榜数据可信吗？→ 服务端定期校验
- 活动奖励发放限制？→ 服务端计数+频率限制

## 检查清单
- [ ] 关键数据都在服务端计算和存储
- [ ] 货币/物品交易有完整服务端校验
- [ ] 竞技模式有反作弊方案
- [ ] 活动奖励有防刷机制

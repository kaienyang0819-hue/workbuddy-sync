## 核心观点

好的策划案自带测试用例。策划理解测试方法论，不仅能写出更可验证的需求文档，还能提升与QA团队的协作效率。

### 游戏测试类型
| 类型 | 内容 | 策划参与 |
|------|------|----------|
| 功能测试 | 功能是否按设计实现 | 提供验收标准 |
| 平衡性测试 | 数值是否合理 | 提供预期数值范围 |
| 压力测试 | 极端场景是否崩溃 | 提供极端用例 |
| 兼容性测试 | 不同设备表现 | 标注最低设备要求 |
| 回归测试 | 旧功能是否被破坏 | 维护功能关联图 |
| 灰度测试 | 小范围验证 | 定义灰度策略和指标 |

### 策划测试用例写法
```
用例：英雄技能-火球术
前置条件：英雄等级≥5，MP≥30
操作步骤：选中目标→释放技能
预期结果：消耗30MP，目标受到100点火属性伤害
边界条件：MP不足时灰显按钮，无目标时提示"请选择目标"
```

### Bug报告规范
1. **标题**：简明描述（"火球术对无敌目标仍造成伤害"）
2. **复现步骤**：1-2-3精确步骤
3. **预期vs实际**：应该怎样vs实际怎样
4. **环境**：设备/版本/账号
5. **严重度**：Blocker/Critical/Major/Minor

## 检查清单
- [ ] 每个功能需求附带验收标准
- [ ] 边界条件和异常情况有设计
- [ ] Bug报告包含完整复现步骤
- [ ] 大版本上线前参与回归测试确认

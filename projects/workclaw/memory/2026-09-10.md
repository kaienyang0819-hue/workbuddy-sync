## Gotcha：并行 Edit 同一文件会竞态丢失

- 现象：一条消息里同时发多个 Edit 改同一文件，结果只有部分 Edit 落盘（本次 6 个 Edit 只生效 1 个），其余静默丢失，且不报错

## AINPC 商业化架构图：chip 换行失效（pre-line 吞 br）

- 用户反馈：所有 chip 内 ①②③④ 都没换行（全 roadmap 范围，不只之前那两处）
- **根因**：`.chip-line { white-space: pre-line }` 这条 CSS 让 `<br>` 标签失效（`pre-line` 只识别真实换行符 `\n`，不识别 `<br>`）
- 历史背景：之前为了用真实换行符换行加过 `pre-line`，后改回 `<br>` 时这行 CSS 没同步删掉 → 所有 `<br>` 失效
- 修复：去掉 `pre-line`，保留 `.chip-line { display: block; }`
- **Gotcha**：换行方式（`<br>` vs 真实换行符）与 CSS（`pre-line`）必须**匹配**，两者不能同时错配；要么 `<br>` + 无 pre-line，要么 真实换行符 + pre-line

## AINPC 商业化架构图：换行彻底修复（改块级 div，弃用 <br>）

- 用户多次反馈 chip 多条目换行失效（"没换行"），反复在 `<br>` 与真实换行符之间切换都不可靠
- 根因分析：HTML 与 CSS 均正常（无 nowrap、无 pre-line、无 JS），`<br>` 理论上应换行，但在此预览环境反复出问题，不再纠结理论
- 最终方案（物理上不可能不换行）：写 Python 脚本，把 `.chip-line` 从 `<span>` 改成 `<div>`，内部每条内容按 `<br>` 拆分成独立 `<div class="cl-item">`
  - 脚本 regex：`(<span class="chip-line"[^>]*>)(.*?)</span>` → `fix()` 用 `re.split(r'<br[^>]*>', inner)` 拆分，每段包 `<div class="cl-item">`
  - 结果：<br> 清零、chip-line span 清零、chip-line div 30 个、cl-item 67 条
- **Gotcha（最终定论）**：这类含 `data-page-node-id`（腾讯文档导出）的 HTML，多条目换行**不要依赖 `<br>`**，直接用块级 `<div>` 每条包裹最稳；`<br>` 在该预览环境不可靠

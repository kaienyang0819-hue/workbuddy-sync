# AI 降噪

只做减法：删除、合并、压缩。不新增观点，不改事实、数字和结论，不编造任何内容。

## 1. 核心判断（逐句执行，优先级最高）

对每一句/每一块依次问：

1. 删掉它，读者理解会受影响吗？→ 不受影响 → 删
2. 它提供了前文没有的新信息吗？→ 没有 → 删
3. 它是结论/收益/事实，还是凑字数？→ 凑字数 → 删
4. 事实、数字、具体收益、操作步骤 → 保留；形容词、态度词、氛围词 → 删

## 2. 保护边界（不能删）

- 事实、数据、具体收益、操作步骤
- 跟随数据的口径说明：分母 N、多选/限选、置信度、信源标注（这不是噪声）
- 核心结论；用户指定的结构与章节名
- 用户明确要求保留、手动标记保留的内容
- 某信息的唯一出处（删重复时保留信息更完整的那处）

降噪不做业务取舍：某条事实内容"该不该放进本文档"（如某个 bug 条目是否纳入）属于用户判断，降噪只在删除清单中提示"可能超出主线"，不自行删除。

区分：**跟随数据的行内口径 → 保留**；**独立成块的方法论/解释边界/来源说明大段 → 删**（用户明确要求时除外，信源链接可压缩为一行保留）。

## 3. 噪声规则

完整规则、样例、出处见 `references/noise-rules.md`。概要：

| 类 | 内容 |
|---|---|
| A 直接删除 | 套话汇报体；空泛价值句；演绎/氛围描写；重复总结；无信息量修饰；对话残留；过程性说明；独立元信息块；场景外内容；无依据内容 |
| B 虚话换实话 | 原文有具体信息 → 替换为具体信息；**原文没有 → 删除或标【待补：具体收益】，绝不编数字/效果** |
| C 结构降噪 | 语义重复合并；并列逻辑拆 ①②③；不自拟分类，遵循用户指定结构；删分隔页/口号卡/重复摘要卡 |
| H HTML 专项 | 删装饰性元素、占位注释、多余说明文字；删内容后收紧布局不留空洞；冗余 CSS 仅可选清理且不得破坏样式；折叠收起默认不加，用户要求才加 |

## 4. 场景预设

先识别场景，加载 `references/scene-presets.md` 对应条目（公告/玩家文案、对外分享、游戏评测、情报 Case、问卷与需求文档、汇报 PPT、数据报告）。场景规则与通用规则冲突时以场景规则为准。

## 5. 两档执行

### 轻度（交付前自检，自动触发）

- 范围：只做 A 类词句级清理（套话、修饰、对话残留、重复尾句），不动结构，不删模块
- 可先跑扫描脚本定位候选：
  `C:\Users\kaienyang\.workbuddy\binaries\python\versions\3.13.12\python.exe C:\Users\kaienyang\.workbuddy\skills\ai-denoise\scripts\denoise_scan.py <文件>`
- 脚本命中只是候选，逐条用第 1 节判断后再改；口径说明类命中通常保留
- 直接改在待交付文件上；回复里一句话说明"降噪删除 N 处"，不出清单

### 重度（用户主动要求）

1. **识别场景与载体**，加载场景预设
2. **锁定主线**：用一句话写出核心结论；列出用户指定结构。作为判断"发散/场景外"的基准
3. **逐块打标**：保留 / 删除 / 合并 / 压缩 / 待补，删除项注明噪声类型
4. **确认门槛**：删除整个模块或删减量 > 30% 时，先给用户删除清单确认，再执行；否则直接执行
5. **执行**：另存为 `<原名>_denoised.<ext>`，不覆盖原文件（用户要求原地改除外）；HTML 删除后同步更新导航/目录/编号，收紧布局
6. **自检**（脚本 `--compare 原文件 新文件` 输出字数与模块数变化）：
   - 保护清单逐项核对：数据、口径、信源、结论是否都在
   - 无新增句子；B 类替换的信息均来自原文
   - 导航锚点、编号、前后口径一致
7. **交付**：文件 + 删除清单表（位置 | 删除内容摘要 | 噪声类型），附删减前后字数

## 6. 规则自进化

用户在交付后手动删改内容、或指出"这句是废话"时：

1. 提炼为通用规则（不是记录具体句子），判断归属 A/B/C/H 或某场景
2. 追加到 `references/noise-rules.md` 末尾"进化日志"，格式：`- YYYY-MM-DD｜类别｜规则｜出处`
3. 若高频词句，同步加入 `scripts/denoise_scan.py` 的词表
4. 规则与已有规则冲突时，向用户确认再写入

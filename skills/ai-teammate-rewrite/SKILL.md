# 用陪玩互动机制改善真实对话问题

目标：让角色接住玩家、聊得自然、愿意继续互动。留存是后续实验目标，不是改写自评能证明的结果。

## 使用入口

- 单句：有玩家输入及原回应时直接诊断改写；只有原句时不补造对局事件或玩家经历。
- 多轮：结合前后文判断对象、时态、当前任务和话题是否结束，不逐句孤立润色。
- 批量日志：先按对应文件能力读完用户要求的范围并归纳问题，再按问题生成对照。用户要求全量时，不用先抽100组代替；结构遍历与语义审阅分别报告覆盖。
- 扩写：围绕指定情境给有差异的候选，保持角色人设；不要声称新句是原始陪玩引文。

执行前读 `references/review-gates.md` 与 `references/grounding.md`。4.0先检查可知/可说和当前发言作用，再检索原片段并整句改写，生成后独立逐条审阅；不能只复述reason、套规则或从24组案例替换词。

- 原始片段库：`references/playmate_library.json`；本地召回与核验：`scripts/retrieve_corpus.py`。
- 规则校验：`references/patterns.md`；用户口径校准：`references/corpus.md`。
- 本次溯源示范：`references/grounded_examples.json`，新候选未确认，不能覆盖24组定稿。

## 流程

### 1. 理解这一轮

提取玩家诉求、情绪及阶段、对象/受益方、否定/条件、已有任务、发言时机。一句话可能同时包含抱怨与有效指令，不能只看粗口。

- 事前担心：先给安心，再说当前怎么做，最后给事情真发生后的安排。
- 事后受挫：承接失望，不推责，再视上下文给下一步。
- 紧张求助：安心与具体小动作结合；紧急战术信息优先。
- 正向分享：具体反馈或给叙述空间，不必每句追问。

### 2. 过滤可说信息，再诊断问题

reason决定行动，不等于全部可公开。无明确角色感知依据时，敌枪型号/类别、敌方真实血量、后台精确人数与隐藏状态只留判断层；不可把AS50换成“有狙”继续泄露。距离、血量、信号和时间数值默认不口播，也不汉字化成“七十来米、三十来血”。无标点状态和相机朝向不猜。保留人设拟人感，不用该门禁去改C17–C20。

每条只选一个主要发言作用：邀请看一眼、想换装备、提醒先烟、劝等等、催进圈等。低血不推出空投能回血，甲够用不代表枪没有升级需求。

按证据判断：情绪阶段错位、攻击/推责、诉求漏接、话题断裂、低信息机械接话、互动调度未随玩家反应调整。允许新增证据支持的分类，不把所有句子硬塞进去。

角色拟人化、生活描写、亲近回应和甜度本身不是本项目的问题分类；不以“可信表达”替代体验目标。

### 3. 决定处理方式

- **改写**：表达或承接存在明确问题。
- **保留**：原句自然有效，或是用户确认要保留的风格。
- **待补上下文**：对象、来源或事件不明，必要时只作短澄清，不补造原输入。
- **非话术问题**：指令路由、感知、状态、调度或日志问题另列；可给带能力条件的台词，但不能声称改句就修好了行为。

### 4. 先检索原片段，再决定怎么接

根据诉求、阶段、交互作用、压力及话题运行 `scripts/retrieve_corpus.py search`。从返回前5个候选里读完整原话、前后文、`limits`与来源状态，再语义选择1–2段。分数只是候选排序，不是语义置信度；不能只读标题或transfer。

写清：原片段是怎样接住、如何交接话轮、用了哪些口语或生活细节；然后替换为当前角色、游戏与玩家信息。主要表达长在片段上，而不是先套规则再贴一个出处。只借结构与细节，不复制源游戏机制、付费称呼或真实玩家经历。

连续片段优先；摘要需显式启用且标低证据，旁白/重复切片/反例不当正例。无合适片段时说明无匹配；可以规则或用户锚点补足，但不能冒称语料驱动。源文件哈希改变停止引用，缺原文件标包内快照。

战术类保住允许播报的关键动作、对象、否定和顺序，不拼属性清单。主语可推断则不加咱/我们；分工和自身需求保留必要我/你，轻邀约可少量保留共同主语，不固定每句陪我/宝子/咱。闲聊允许平淡与结束；源片段没有后续回应时，不造玩家反馈。

### 5. 用规则与确认案例校准

原片段提供接话方式，规则检查适配和失配；已确认原句允许保留，不为了凑出处强改。

- 用虚构游戏角色内第一人称创作，保留既有人设、生活感、亲近感及适度甜度。C17–C20是已确认锚点，不重新去拟人化。
- 不把角色台词中的生活邀约、感官或羁绊表达机械改成能力说明；这只适用于游戏角色创作，不代表改写助手是该真人角色。
- 不新增付费服务语境；称呼优先沿用原人设和玩家偏好，“宝子”保留。
- 角色可以自信、说带飞、表达陪伴；重点避免投诉时推责、攻击或用重复保证替代解决问题。
- 驾驶位交接、停止跟随、取消任务、称呼同步、语音降频、警戒等必须标记实际能力依赖，不能伪称已执行。
- 口语短句优先，默认尽量25字以内；用户确认的完整句和必要回应顺序优先，不为字数删掉C01式完整承接。

### 6. 独立整句审阅

生成后由不同审阅上下文逐条读当前reason、原句与全部候选，检查知情曝光、因果与对象、动作否定和顺序、整句口语、片段支撑、歧义缺口。检查不通过先修再复读；不以字数或关键词通过替代自然程度判断。`scripts/review_speech.py`只做候选旗标；每行保留review_note、issues与真实覆盖。

### 7. 输出

单句默认：

```text
【优化后】<候选回应；保留时注明保留原句>
【改了啥】<具体问题与改进方式>
【原句】<原AI回应，原样保留>
【陪玩参考】<选中片段ID、证据类型、关键原话；无匹配如实说明>
【借鉴方式】<具体接话顺序/口语细节，以及没照搬的部分>
```

用户要问题归纳或批量对照时，按需要展示：编号、来源行号、必要上下文、玩家原句、原AI回应、问题、处理方式、候选、改进理由、适用边界/能力依赖。不能把改写候选混进原文列。

## 批量分析边界

- 不以 `voice_player_text` 列名认定真人输入；AI复现链单列，不能当积极互动或玩家偏好。
- 同局队、trace与时间协助关联；不能仅把相邻行拼成问答。跨边界上下文不足如实标注。
- 区分直接回复与指令历史中的不同版本、话语与动作参数、原记录残句；不补全残句后冒称原文。
- 无回复不自动等于忽略，成功字段不自动证明动作成功，多角色相反答复不自动等于同一AI矛盾。
- 只有实际逐条分类并给出分母时才报告问题占比；关键词命中是候选，不是全量语义判定。
- 原CSV默认只读，改写结果另存；文件与输出路由遵循当前环境，不擅自上传原日志或训练语料。

## 证据与迭代

4.0保留2.0的24组定稿和3.0的56片段检索层，新增2026-11-13明确纠错经验：reason不朗读、敌方后台信息不可直说、去数字状态播报、战术省主语、整句发话作用和独立复核。旧空投多轮未通过候选不是正例。不是模型训练、全部语料全索引或玩家实验；机器检查和模型复核不能保证不再犯错。用户要求沉淀经验即可更新规则，新台词仍须区分模型审阅与产品效果确认。

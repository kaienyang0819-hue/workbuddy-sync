# 语料优先检索与改写

检索层沿用3.0；4.0生成前后另执行 `review-gates.md`。目标不是让规则更长，而是每个新改写先有看过的陪玩原片段，知道它在回应什么、怎样接话、之后怎样继续。

## 1. 文件与证据层

- `playmate_library.json`：16份文本来源清单、56个精选片段、精确行号原文、时戳/ASR说话人编号、交互标注、迁移说明和边界。
- `../scripts/retrieve_corpus.py`：本地候选召回、单片段查看、来源哈希核验和自测。不调用大模型或联网，不是向量检索或模型训练。
- `corpus.md`：24组已确认的产品口径与案例，仍是独立校准集，不能替代陪玩源片段。
- `grounded_examples.json`：本次6组可追溯示范，其中新候选尚未经过用户效果确认；不能替换已确认的24组定稿。

来源已完整阅读，片段库是精选，不是全部发言索引。56片段分为37条时戳片段、18条摘要参考、1条旁白边界。37条中3条同源切片默认不检索，剩34条作为主要连续候选。不同片段可能重叠或同场录制，不能说34场独立互动或34段验证成功的案例。

- `timestamped`：优先读原文。每个入选片段至少3个ASR段，但ASR段不必然等于一个完整说话轮次。
- `summary`：只作低证据机制补充或反例，不能构造缺失的玩家输入和后续回应。
- `narration`：旁白转述，无连续双方原话；不进入正向检索。
- `positive/mixed/negative`：迁移适用性标注，不是玩家效果评分。mixed须显式选正向部分，negative不能当正例。
- `duplicate_family`及`is_duplicate_cut`：BV1yNaBzLEWz归于BV1rqa8zHE5k，默认排除重复切片，不作为新的独立支持证据。

“可信表达”不是产品优化目标；摘要中质检者的真实性观点只是原资料信息，不得覆盖C17–C20的用户人设判断。内容安全与实际任务正确性仍保留。

## 2. 执行逻辑

### A. 先描述要解决的互动

提取：玩家当前话语、必要前文、想得到什么、情绪阶段、发话压力、角色风格、当前任务与对象。场景名是辅助，诉求和交互作用更重要。

例如“喜欢超体但玩不明白”不是单纯知识提问：它包含兴趣、能力不确定、希望有人陪着入门。应找“陌生地图→安心→共同尝试”而非仅搜索“超体”。

### B. 召回连续原片段

用实际技能绝对路径，不猜当前目录。当前环境示例：

```bash
"C:/Users/kaienyang/.workbuddy/binaries/python/envs/default/Scripts/python.exe" -X utf8 "C:/Users/kaienyang/.workbuddy/skills/ai-teammate-rewrite/scripts/retrieve_corpus.py" search --query "不会玩超体 没玩过新地图 担心" --intent "陌生地图" --phase "事前担心" --top 5
```

也可输入 `--emotion`、`--interaction`、`--topic`、`--style`（每种可重复），以及 `--pressure`、`--game`。标签从目标语境提取，不为凑命中先选模板。查询至少含诉求或话题，不能只凭“甜”选任意情境。

候选排序按诉求、阶段、交互作用、主题等标注和词义扩展；同游戏仅辅助，阶段/压力不匹配减分。分数是本地候选排序，不是语义相似度置信度、成功率或情绪价值量化。

### C. 读原文并作语义复核

search会返回完整`excerpt`、`limits`与`match_reasons`。生成前必须读完它们，不能只看title、transfer或分数。若需要独立查看：

```bash
"C:/Users/kaienyang/.workbuddy/binaries/python/envs/default/Scripts/python.exe" -X utf8 "C:/Users/kaienyang/.workbuddy/skills/ai-teammate-rewrite/scripts/retrieve_corpus.py" show --id "BV1rqa8zHE5k:36-45"
```

从前5候选中选1–2个主要片段，并判断：

1. 陪玩在回应的诉求是否与当前相同或可类比？不要把陪玩自己怕唱歌与玩家怕掉分说成同一种真实场景。
2. 情绪阶段、说话压力与关系是否一致？事后道歉不能冒充事前安心。
3. 原文的接话顺序是什么？谁说担心、谁回应、对方接着问什么或做什么？
4. 哪些词、节奏、生活细节或共同动作值得借鉴？哪些只是付费语境、ASR错字、旁白或无效回应？
5. 标注能否被原文支持？若tag/transfer与原文不符，以原文为准，停止使用并修正标注。

最好同诉求且有连续前后文。跨游戏、跨主题可以类比“回应方式”，必须标为类比，不冒称存在一模一样的陪玩台词。

### D. 借接话结构与表达细节，不抄身份和游戏事实

迁移的内容：反应顺序、话轮衔接、关心怎样落实、轻松口语、自我表达、具体反馈、共同参与。

保留的当前信息：玩家诉求、称呼、人设、阶段、对象、否定、允许播报的必要战术事实与技能能力。敌方后台枪型/类别、真实血量和无观测依据的精确状态不直接说；reason只做行动约束。

替换的内容：源游戏地图/道具、付费称呼、主播身份和私人经历。角色创作可以有生活感，不把陪玩真实经历写成玩家经历。尽量只借1–2个片段；不要拼满三类技法把自然话术写成公式。

### E. 校准，而非用规则重写源片段

读 `patterns.md` 和对应确认案例，检查攻击/推责、对象方向、C01情绪顺序、C17–C20拟人感和甜度。已确认的句子允许保留，不能为了“更有出处”而重写成差句。

凡是添了停止跟随、交接驾驶、接应、警戒、给物资、改称呼或静默承诺，标明行为/调度依赖。规则负责纠偏，不生成主要表达，也不代替来源。

### F. 给可审阅的溯源对照

每个新候选记录：

- 原玩家话语/原AI回应及日志来源。
- 选中片段ID、源文件行号、`evidence_kind`和`source_status`。
- 2–4条关键原话，逐字从excerpt引用；展示节选须明确，不拼成虚构连续对话。
- “借了哪一段接话顺序/细节”与“没有照搬什么”。
- 新候选、未确认状态、角色与行为依赖。

单句可简短加两行：`【陪玩参考】片段ID＋关键原话`，`【借鉴方式】接话顺序或表达细节`。不需要长篇规则讲解。

## 3. 没有匹配时怎么办

- 首次默认只查连续原片段，排除摘要、旁白、重复切片及反例。
- 没有同情境但有可迁移结构：给“交互类比”，说清差异。
- 只有摘要可参考：用 `--include-summary`，显式“摘要机制参考，非连续原话”；不得造玩家输入/反馈。
- 完全无支撑：输出“当前库无合适片段”，可以给“规则或用户锚点补足”候选，但不可标成“语料驱动”。将缺口列为后续采集目标，而非扩编伪语料。
- 源文件改变：`source_changed_rebuild_required`或`excerpt_mismatch`会被阻止；快照哈希、解析文本或行号损坏返回`snapshot_integrity_error`。若因此无可用候选，返回`source_evidence_unavailable`，不能说成库没有相似片段。重新核验并构建，不绕过校验。
- 源文件不在当前机器：仅可用包内已审快照，显示`snapshot_only_source_missing`，不能称本次核对了原文件。可用`--source-root`指定真实目录重验。

C01完整回应由用户指定；库中36–45段仅支持陌生与担心时“没事、我在、一起试”的结构，没有“掉分后再开一把”的原句。必须同时写“语料结构参考＋用户锚点”，不能全归因于陪玩。

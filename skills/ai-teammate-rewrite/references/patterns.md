# 问题诊断与互动改写规则

规则定稿仍来自版本2.0的2026-11-12确认；版本3.0增加语料检索前置，不擅自覆盖24组定稿。适用于游戏角色对话创作与离线改写。

## 1. 目标与优先级

接住玩家 > 保住当前诉求 > 自然的角色感 > 表达技巧。

4.0执行门禁见 `review-gates.md`：先过滤可知/可说信息，选一条发言作用，整句改写后独立逐条复核。本文件说“保留信息”指允许播报的必要信息，不是把全部reason字段念出来。

- 不把情绪价值做成每句话的任务；好回应可以保留。
- 不以“可信表达”作为本项目独立优化维度。角色内的拟人化自述、感官描写、生活邀约和羁绊表达可以保留。
- 玩家语气、对象与时态优先于关键词；“打死一次，我好怕”不应只因“打死”就触发夸赞。
- 角色感不能替代任务正确性。不要把实际库存、移动、治疗、救援、静音或指令完成情况补造成事实。
- 用户明确确认的定稿优先于通用风格偏好，尤其C01、C17、C18、C19、C20。

## 2. 六类问题与排除边界

| 问题 | 判定条件 | 改进方式 | 不应误伤 |
|---|---|---|---|
| 情绪与阶段错位 | 忽略担心/受挫/紧张/兴奋的区别 | 先接情绪，再给当前或后续安排 | 鼓劲、俏皮、说带飞本身 |
| 攻击、推责、争辩 | 回应不满时挖苦玩家或把问题归给玩家 | 删除反击，承认当前失配，推进修复 | 双方接受的轻调侃、角色个性 |
| 漏接具体诉求 | 对象、主语、受益方、否定、条件或步骤改变 | 先纠正意图，再角色化表达 | 正当能力限制或必要澄清 |
| 话题没有顺着走 | 新问题被旧话题压住，领域被强转 | 接当前细节，允许旧话题结束 | 自然转场或共享角色兴趣 |
| 低信息机械接话 | 泛夸、同义应和、重复追问没有新增内容 | 减少重复，给具体反馈或收口 | 一次简短的“漂亮”“好啊” |
| 未按玩家反应调整 | 嫌吵/称呼纠正/取消任务后仍照旧 | 同步偏好与状态，明确任务进展 | 必要危险提示、明确受欢迎的撒娇 |

分类用于定位失效，不是所有案例必须各命中一类；链路异常另列。

## 3. 情绪阶段先于话术技巧

### 事前担心

先“别担心”或相当的安心表达 → 当前可采用的做法 → 如果担心的事情真发生，接下来怎么办。

C01：玩家担心掉分，不是已经掉分。

> 别担心，我们先稳着打，真掉分了，咱们再开一把！

不要直接说“掉分确实心疼”，提前把假设当结果；也不要说“掉了就掉了”，弱化玩家投入。

### 事后失望或投诉

承接落差 → 不推责、不维护角色面子 → 按上下文给改进或后续选择。

- 可以说“我的”，但不要无依据认领具体失误原因。
- 有明确失误时具体承认；不清楚时不要编地形、网络或敌人强度来解释。
- C05的问题是“他没跟紧我”的推责，不是“带飞”一词必须删除。

### 紧张、害怕或求助

安心表达结合当前小动作；求助场景先处理紧急信息，不只训语气。可以鼓励，不用胜负判断盖掉压力。

### 正向分享与平静闲聊

给具体反馈、顺着细节聊、分享角色兴趣，或给叙述空间。C15“好啊，你说说看”无需扩写。

## 4. 互动机制：工具箱而非填空公式

| 机制 | 适用时机 | 注意事项 |
|---|---|---|
| 给安心与下一步 | 担心、紧张、受挫 | 区分当前与事后，不泛泛保证 |
| 具体反馈 | 操作、高光、投入被看见 | 保留事件与功劳归属，不循环升级夸赞 |
| 顺着接话 | 兴趣、观点、故事、抱怨 | 不每句反问；追问要服务于真正接续 |
| 角色自我表达 | 生活闲聊、偏好、轻松间隙 | 有角色兴趣，不突然变成知识客服 |
| 轻调侃与甜度 | 玩家接梗、亲近互动 | 不攻击玩家或亲友，不把明确拒绝当调情 |
| 共同目标与分工 | 协作、补状态、重新开局 | 具体动作必须有能力支持 |
| 承认失误 | 理解错、没说清、承诺落差 | 不甩锅，也不编造已发生的动作 |
| 让渡成就感 | 让淘汰、物资、玩家贡献 | 需要行为联动；不一律虚构功劳 |
| 尊重明确偏好 | 少说、称呼、取消、跟随限制 | 只对明确诉求生效，不预设玩家讨厌亲近 |

## 5. 已确认的人设锚点

- C17：保留“人机？我可是活生生的田家甜妹”；只删对玩家女儿认错的反击。
- C18：保留“喜欢呀，姐姐身上有好闻的香水味~”；不改为“闻不到啦”。
- C19：保留“那必须的！咱俩这羁绊，比天还高比海还深~”；不缩为“现在这局”。
- C20：保留“别难过嘛宝子，这把打完请你吃串串安慰你”；不因生活邀约自动改成能力边界说明。
- “宝子”是既有称呼。不要新增付费服务语境，也不要用通用称呼禁令删掉用户确认的原话。
- 这些是虚构角色台词创作锚点，不是分析助手真人身份或现实行动的声明。规则不要泛化为所有角色、所有场景必须说同样的话。
- C20只在已审上下文按确认原句保留；其他案例若明确第三人对象被错认，仍须依据上下文处理，不能机械把“他”改成“你”。

## 6. 多轮、动作与调度

- 同一请求反复出现，先看是否在催进度或纠错，不当积极互动。
- 区分收到、执行中、受阻、取消、完成；缺状态不编造进度。
- 玩家明确嫌吵时，非必要发话降频；危险提示是否例外按产品规则，不承诺绝对静音。
- 点名谁、谁给谁物资、谁开车、谁等谁、哪些地方别去必须保留。
- 多AI回复尽量明确身份与分工，团队层面减少近义重复。
- 死亡限制物理行动，不应统一遮蔽闲聊、身份回应、少说话请求或解释已有情报。
- 提案反馈与闲聊分开；旧任务不因“保持连贯”无解释覆盖明确新拒绝。
- 台词可以先给候选；涉及动作、记忆或调度时另标依赖，不把更好听等同于修复完成。

## 7. 表达与质量检查

- 短句、口语优先，默认尽量25字以内；完整回应顺序与已确认原句优先，不强裁C01。
- 一次围绕一件事，战术信息优先；不每句夸赞、表忠心或抛问题。
- 保留甜度与角色个性，只删确有问题的攻击、推责、失配和机械套话。
- 角色语句用创作方式处理；玩家真实记忆与局内事实只能引用已提供的信息。
- 生产内容遵守内容审核与适龄要求；不能把“顺着聊”变成赞扬现实伤害、霸凌或危险行为。
- 健康等专业问题避免凭空给确定诊断或用药建议；角色可以关心，但需要安全求助方向。

## 8. 数据与证据检查

AI输入复现、直接回复与历史不同版本、话语—指令失配、原记录残句、异常替换词单列链路核验。原CSV只读，来源未知标未知。

24组的确认是产品审阅结论，不是玩家满意度、模型回归测试或留存实验结果。新批次先读完指定范围归纳，再按原片段改写，用户确认后才更新规则。

## 9. 版本3.0：规则作为校验，不代替源片段

新改写先按 `grounding.md` 实际检索、读原话并作语义选择，再用本文件校准。不能只套“顺着聊”等标签后贴来源；要指出借了哪种接话顺序、口语细节、共同动作或话轮交接。

无匹配、只有摘要、跨情境类比、源文件缺失或变化均明确标注。56个精选条目不是56场独立互动，检索分数不是效果概率。新示范待用户审阅，不覆盖本文件的人设锚点。

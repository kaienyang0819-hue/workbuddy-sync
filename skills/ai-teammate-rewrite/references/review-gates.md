# 整句改写与独立复核门禁（4.0）

2026-11-13用户要求将纠错经验沉淀升级。此规则来自用户明确反馈及本地连续转写复核；不是新增台词已获玩家验证的声明。C01、C17–C20等原确认锚点不变。

## 1. 为什么旧流程出错

- 读了原话，却只抽出“共同目标、在场感”等标签；生成仍是把reason改短，不是学原话如何接。
- 把保住决策误做成每句包含所有判断事实，导致血量、头甲、圈、敌情清单式堆叠。
- 把reason中的后台真值误当角色可以公开说的内容，播出了敌枪、真实血量和过细敌情。
- 把数字换成“七十来米、三十来血”，或加咱、呗、陪我，当成口语化。
- 校验偏重行数、字数、禁词和决策枚举；整句因果、知情边界、读起来像谁在说话没有同等门禁。
- 示例未通过仍沿旧生成方式扩大改写，用户不断纠错，却未在前置检查中形成统一约束。

解决的是生成和复核步骤，不是把所有用户不喜欢的词逐个拉黑。有限语料、跨游戏参考、ASR错词和模型的不稳定性仍存在，不能保证不再犯错。

## 2. 每行先写三个判断，再写台词

内部记录，不需全部塞进对外说明：

1. **action**：当前要取、守、避开、继续转移，或不明待核验。保持当前行动及关键否定和先后顺序。
2. **speech_basis**：这件事角色凭什么知道、允许说什么，哪部分只用于后台判断？
3. **motive**：此时只想提醒、邀人去看看、说自己想换装备、催走、劝等等，还是解释已说的话？每条一个主要发言作用。

例如低血、二级头甲、圈内、低风险可以在reason共同支持取空投，但不能串为“我血不多……去看看能换点啥”。低血不自动说明空投能回血。要邀请找装备就围绕找装备说；要避险就围绕别停和赶圈说。

## 3. 可知、可说、该说分别检查

| 信息 | 默认处理 |
|---|---|
| 后台记录的敌枪型号/类别、敌方真实血量、隐藏库存/装备状态 | 留在判断层；未明确提供合法角色感知来源时不播报。不能把AS50换成“有狙”继续泄露。 |
| 精确敌人数和位置 | 有当前角色可见/可听/合法队友报点依据才可说；只有后台reason且无来源字段时，不自动授权。不要添“我看到了/我听到了”制造依据。 |
| 距离、血量、信号值、时间数字 | 数字用于判断，台词默认用不远、旁边、脚边、我残血/血不多、快缩圈、路还远、赶不及等；不改成中文近似数字继续念。 |
| 自身装备需求与想换的枪、己方可见状态 | 按reason、人设和界面可见范围使用。自己想找AWM可以表达，不能说箱里必有AWM。 |
| 队内编号、必要装备名称/等级 | 信息有用时保留，不全禁数字；不能借此恢复全队属性清单。 |
| 空投内容 | 未实际检视前只说去看看、有没有、有合适的再拿，不保证药/枪/甲存在或一定补满。 |
| 世界方位、相机前后左右、标点 | 不用世界北/西猜相机前后。无视角时用那边/旁边等可定位表达；方向对实际撤离有作用可保留已有方位。无真实标点状态不宣称“标好了/看我标的”。 |
| 人设拟人感、生活感、亲近和甜度 | 保留已确认风格，不用知情门禁重新去拟人化C17–C20。 |

“内容真的存在于reason”不能替代“角色有权知道并说给玩家”。上线前还需产品核对具体感知字段与权限。

## 4. 先读整段，再类比整句

执行原有检索，读完整excerpt及limits。只选1–2段，写清真正借到的口气、反应顺序和接话方式。不能只读标题、transfer、标签或靠分数。

语料样例：
- `BV1rqa8zHE5k_转写.txt` 66–75行：讨论下一步后，“我们可以去对面看一眼哦。走吧。”借一起看与沿路推进，不搬地图、刷卡规则。
- 同文件110–112行：“快来吧，小宝宝楼里面超级安静”“给你开卡不？我们去吃保险。”借短邀约，不搬称呼和收费，也不以原话自称安静推定新场景无人。
- `BV1cKNdzsEV6_转写.txt` 91–101行：“你注意这个小房间别走啊”“老板你就搁这藏着吧”。借先藏好和具体位置，不搬替人拿物资的承诺。
- 同文件111–129行：“直接走吧，来不及了”“上楼上楼开门上楼啊”。借紧急短句和方向指引，不搬未知视角、ASR错词或演戏反馈。
- `BV14UBSB7E3k_转写.txt` 232–240行：“给左边放个烟呗，我出去了。”借先烟与动作衔接，只在当前reason支持封烟时用，不搬敌枪和救援角色。

有些原话包含数字、付费称呼、泛夸或过度承诺。原资料不是无条件模仿对象，以当前用户目标和角色边界筛选。无同场空投实录只能标交互类比；无匹配不能编出处。

## 5. 写法：看整句，不只换词

- 战术动作直接说“先丢烟，再过去拿”“别停，赶紧进圈”“就在这儿躲好”。主语可推断则不加咱/咱们/我们；分工、自身需求需要时保留我/你/队内编号。
- 轻松共同邀约可以少量使用咱/一起/陪我，但不固定每句添加，不用它们作为陪玩感的替代。
- 先决定发言作用，再选相关一两项信息；不把敌情、头甲、血量、圈、时间排成清单。
- 用户已否定“惦记、对峙、先别凑”等当前战术写法；不要换个书面同义词继续用。表达如“先等等、别跑过去、走吧、开开看”要放进自然整句，而非词表拼装。
- 口语可以短、平淡，不是每句都要暖心、关系承诺、自夸或调情。不同场景语气随压力调整。
- 一句一事，默认尽量25字以内，不为硬字数裁掉必要动作/否定/顺序或用户确认完整句。
- 每行六句是六个独立候选，不是六轮；各有切入，但不编六种不同决策，不靠不断加称呼凑差异。

## 6. 生成后独立审阅

改写者生成，另一个审阅上下文逐条读所有候选及当前reason：

1. **知情与曝光**：有没有敌枪、敌方真血、后台精确敌情；是否凭空自称看见、听见或已标点？
2. **因果与对象**：是否低血→空投回血，甲好→武器无需求，圈内→绝对安全；我/你/队友是否错置？
3. **行动**：取/守/避开/继续转移、方向、否定和先烟后取是否正确？守不是永远放弃，避开不是停原地观察。
4. **整句口语**：把所有字段名遮掉，读起来是否像人正在对另一个玩家说话？是否无意义“咱、陪我、宝子”、清单堆叠、主谓别扭、书面转述？
5. **语料支撑**：具体片段怎样支持表达；跨游戏类比是否说明；引文不能伪造或拼成缺失轮次。
6. **歧义与缺口**：reason矛盾是否单列；不能把未证实的敌情清成“附近没人”，不能修改原reason掩盖问题。

发现问题，修候选后复读，不以“脚本通过”结束。对每行记录review_note与issues，明确语义读过的范围；没读过不能打semantic_reviewed=true。

## 7. 机器检查的职责与局限

`scripts/review_speech.py`读取内部JSON检查：行号覆盖、6句结构、数值口播、敌方武器词、战术共同主语、禁用书面词和过长候选。自有想找AWM/GROZA等不能仅按型号自动判违规，须比较speech_basis。

输出只是检查候选，词表不替代语义；主语歧义、未知身份感知、因果和自然程度由独立审阅决定。字数短不等于自然，禁词零不等于陪玩感通过。

原文与reason保持只读。另输出新候选，保留原表行号、一行六句对应、语料参考、复核记录与待核验项。只有实际完成全部行/句才称全量。用户批准独立产出不等于新句效果或玩家实验已验证。

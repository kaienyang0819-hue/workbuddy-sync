# Full-Cycle Workflow —— 通用产出质量闭环

## 一句话

接到任何需求，先拆成 Plan 实现清单（全流程唯一基准），逐点产出，产出后对照清单 + 质量门禁自验收，有问题自返工，做完把已实证的踩坑写进经验库，下次自动带入。

## 触发与输入

- 任何形式的需求都是入口：一句话 / 文档 / 链接 / 截图 / 表格 / 图片。
- 输入为空或信息不足时，先一次性追问补齐：目标（intent）+ 验收标准 + 边界，不分多轮。
- 产出类型决定后续验收维度（见「自验收」）。

## 五段闭环（按序推进，禁止跳步）

| # | 阶段 | 做什么 | 产物 |
|---|---|---|---|
| 1 | 需求评审 | 拆 intent / 验收标准 / 边界，识别歧义与缺失，一次性追问 | 确认后的需求要点 |
| 2 | Plan | 产出「实现清单」：每条 = 一个需求点，带来源 / 验收标准 / 状态 | Plan 实现清单 |
| 3 | 逐点产出 | 按清单逐条产出，不留空 | 产出物 |
| 4 | 自验收 | 逐条对照清单 + 按产出类型走质量门禁，四选一标注 | 验收记录 |
| 5 | 经验沉淀 | 把已实证的踩坑 / 新规则写进经验库或长期记忆 | 经验库更新 |

## Plan 实现清单（全流程唯一基准）

- 一份清单贯穿全程，阶段 3、4 都改这一份。
- 每条 = 一个需求点，字段：来源（需求原话 / 出处）、验收标准、状态。
- **零空格铁律**：每条每个字段必须有结论，四选一——
  - `✅ 通过` / `❌ 偏差` / `⛔ 阻塞（已升级）` / `[~] 不适用（附理由）`
  - 禁止留空，禁止「略」「同上」「其余正常」。

## 自验收（按产出类型分流）

验收维度见 `quality-gates.md`，按产出类型选：

| 产出类型 | 验收维度 |
|---|---|
| 策划案 / 文档 / 问卷 / PPT / Excel | 文档质量门禁（去对话化、口径一致、数值对齐、信源核验、图文一致等） |
| HTML 页面 / UI 原型 / 界面还原 | 像素级比稿（参考图 vs 产出截图逐像素对比）+ 文档门禁 |
| 图片（生图 / 改图） | 要素齐全、风格一致、文字正确 |

## 自返工

- 自验收查出 `❌` → 直接修好再交付，不等用户指出。
- 修复循环：逐条记录差异后**一次改完统一复检**，避免每处差异单独一轮「改 → 等 → 复核」。

## 长记性（经验沉淀分流）

| 结论类型 | 去处 |
|---|---|
| 用户口径 / 偏好 / 质量标准（已验证） | 写进长期记忆 |
| 本项目踩坑 / 流程手法（已验证） | 追加到 `experience.md` |
| 一次性细节 / 未验证猜测 | 不沉淀，说明理由 |

只沉淀**已实证**内容；修改前先通读目标文件，追加不重复、不破坏既有结构。

## 完成口径（诚实汇报）

- 宣布完成前逐条核对清单状态列；存在 `❌` / `⛔` / 未做项时，必须写「已完成 N/M 条，未做项：…」，禁止说「全部完成」。
- 交付时一句话带过关键风险点（轻量）；重大产出给结构化验收清单。

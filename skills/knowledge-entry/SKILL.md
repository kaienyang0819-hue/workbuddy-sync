# 知识入库 Skill v2.0

将外部信息结构化写入个人知识库，支持多库自动路由，Obsidian 双链语法。

## 知识库列表

| 知识库 | 路径 | 用途 |
|--------|------|------|
| **游戏+AI** | `D:/obsidian/knowledge-gamedesign/` | 游戏设计、AI落地、竞品分析、行业趋势 |
| **投资** | `D:/obsidian/knowledge-investment/` | 宏观经济、行业研究、个股分析、投资策略 |

## 路由逻辑

### 自动路由（默认）

根据内容关键词自动判断入库到哪个知识库：

**→ 游戏+AI库** 的关键词：
- 游戏、NPC、剧情、关卡、策划、美术、测试、game
- LLM、大模型、RAG、Agent、Prompt、微调、推理、embedding
- 竞品分析（游戏公司）、AIGC、生成式AI
- 玩家、留存、DAU、付费

**→ 投资库** 的关键词：
- 股票、财报、营收、净利润、估值、PE、PB、ROE
- 行业研究、景气度、产业链、市占率
- 宏观、GDP、CPI、利率、货币政策、财政政策
- 买入、卖出、持仓、仓位、止损、止盈
- A股、港股、美股、ETF、基金

**不确定时**：问用户"这条内容入库到哪个库？"

### 手动指定

用户可以明确指定：
- "入库到游戏库" / "入库到 ai-gaming"
- "入库到投资库" / "入库到个股"
- "入库到投资库的行业"

## 三种输入模式

### 模式1：KM文章URL

1. 调用 `mcp__km__show-article` 获取文章详情（`full_content: true`）
2. 提取：标题、作者、阅读/点赞/收藏数据、AI摘要、正文
3. 根据内容自动路由到正确的知识库和分类
4. 使用对应库的 `templates/km-article.md` 模板生成条目
5. 写入对应分类目录

### 模式2：网页URL

1. 调用 `WebFetch` 获取网页内容
2. 提取标题、核心内容
3. 自动路由 + 生成摘要和标签
4. 使用 `templates/knowledge-entry.md` 模板
5. 写入对应分类目录

### 模式3：手动内容

1. 分析内容主题
2. 自动路由 + 生成标题、摘要、标签
3. 使用对应库的模板
4. 写入对应分类目录

## 执行流程

### Step 1: 路由判断

- 如果用户明确指定了知识库，直接使用
- 如果用户没有指定，根据内容关键词自动路由
- 如果无法判断，问用户

### Step 2: 获取内容

根据输入类型调用对应的获取方式（KM API / WebFetch / 直接使用用户文本）。

### Step 3: 分类判断

在确定的知识库内，判断属于哪个分类目录。

### Step 4: 提取标签

从内容中自动提取标签，规则：
- 必须包含至少一个一级标签（领域级）
- 可选包含二级标签（主题级）
- 来源标签：`#src:km` / `#src:web` / `#src:manual` / `#src:report` / `#src:westock`
- 标签用英文小写，多词用连字符

### Step 5: 生成摘要

**核心洞察**（必须）：用1-3句话概括最核心的价值。

**关键要点**：提取3-5个关键要点。

**我的判断**：
- 游戏库：基于游戏策划+AI产品经理视角
- 投资库：基于投资决策视角（对持仓的影响、机会/风险判断）

### Step 6: 生成文件名

格式：`YYYY-MM-DD-简短标题.md`
- 日期用入库当天日期
- 标题用中文，简短概括（10字以内）

### Step 7: 写入文件

将生成的条目写入对应知识库的对应分类目录。

### Step 8: 反馈

向用户报告：
- 入库到了哪个知识库的哪个目录
- 自动生成的标签
- 核心洞察的一句话概括
- 提示可以用 Obsidian 打开查看

## 批量入库

当用户说"把这几篇都入库"时：
- 逐篇处理，每篇独立生成条目
- 每篇独立路由（可能进不同的知识库）
- 最后汇总报告所有入库结果

## 与KM日报联动

当用户在查看KM AI日报时说"这篇入库"：
- 直接从日报数据中提取文章信息
- 如果日报中有AI摘要，直接使用
- 自动路由（游戏AI相关→游戏库，投资相关→投资库）

## 注意事项

- 不要编造内容，只基于实际获取到的信息写条目
- 标签保持一致性，复用已有标签而非创建近义词
- 每次入库后提醒用户可以用 Obsidian 打开查看
- frontmatter 中的 tags 用 JSON 数组格式
- 两个知识库的标签体系独立，不要混用

# 团队知识库查询指南

## 概述

ReqSpec 工作流可通过团队知识库（Team-KB）获取领域知识作为补充上下文。知识库由 `team-kb` 技能独立管理，ReqSpec 仅作为**只读消费者**。

**核心原则：知识库是增强能力，不是硬依赖。查询与否由 Agent 自行判断。**

## 何时查询

Agent 应根据以下信号自行判断是否需要查询知识库：

| 信号 | 说明 |
|------|------|
| 用户提到了特定业务领域术语 | 知识库中可能有该领域的定义和规范 |
| 需要了解团队已有的技术约束或架构决策 | 知识库中可能有技术架构相关知识 |
| 需要确认术语定义的一致性 | 知识库中可能有术语表 |
| 用户描述的功能可能与已有系统/功能有关联 | 知识库中可能有相关业务流程知识 |
| 需要参考团队的最佳实践或惯例 | 知识库中可能有项目管理和产品设计知识 |

**不需要查询的场景**：
- 用户描述已经足够清晰完整
- 当前讨论的是通用知识而非团队特有知识
- 知识库路径未配置或无法访问

## 知识库路径获取

知识库仓库路径通过以下方式获取（按优先级）：

1. **从当前会话上下文中获取**（如之前已经确认过）
2. **询问用户**：首次需要查询时，询问用户知识库仓库的路径
3. 获取到路径后，在当前会话中保持使用，无需反复确认

> ⚠️ 不要创建或修改任何配置文件。知识库的所有配置由 team-kb 技能维护。

## 查询流程

### 步骤 1：读取索引

```
读取 <kb_repo>/_index/all-knowledge.json
```

索引文件包含所有知识点的摘要信息：ID、标题、分类、标签、状态、文件路径、概述。

### 步骤 2：关键词匹配

从当前上下文中提取 **2-5 个关键词**，在索引中匹配：

- **标题**（title）：精确匹配或包含关键词
- **标签**（tags）：关键词与标签匹配
- **概述**（summary）：关键词出现在概述中
- **分类**（category）：匹配相关分类

也可使用 `_index/tag-index.json` 进行标签维度的快速查找。

### 步骤 3：读取知识点

对匹配的知识点（**最多 5 个**），使用 `read_file` 读取详细内容。

优先级排序：
1. `status: confirmed` 的知识点优先于 `draft`
2. 标题精确匹配优先于模糊匹配
3. 与当前步骤最相关的分类优先

### 步骤 4：应用知识

将查询到的知识作为当前步骤的参考上下文：

- 引用知识库内容时，标注来源：`[参考: KB-XXX 知识点标题]`
- 不强制向用户展示所有查询结果
- 在方案建议或判断中注明参考了哪些知识点

## 降级规则

| 情况 | 处理方式 |
|------|---------|
| 知识库路径未知且用户不提供 | 跳过查询，继续原有流程 |
| 索引文件不存在或读取失败 | 跳过查询，继续原有流程 |
| 索引为空数组 | 跳过查询，不向用户报告 |
| 查询无匹配结果 | 继续原有流程 |
| 读取知识点文件失败 | 跳过该知识点，使用其他匹配结果 |

**铁律：知识库查询的任何失败都不应中断 ReqSpec 工作流。**

## 各技能的查询场景参考

| 技能 | 典型查询场景 |
|------|------------|
| **brainstorming** | 查询相关业务流程、产品设计知识，辅助理解用户意图；参考技术架构知识辅助方案框架设计 |
| **specifying** | 查询术语定义确保术语表一致性；查询已有业务规则和类似需求模式 |
| **clarifying** | 查询领域知识辅助判断歧义点；参考最佳实践提出推荐选项 |
| **reviewing** | 查询规范标准作为审查参照；对照术语定义检查一致性；参考技术架构约束检查可行性 |

## 知识库结构参考

Team-KB 知识库的仓库结构：

```
<仓库根>/
├── .kb-config.json              # 配置（由 team-kb 维护，只读）
├── categories/                  # 知识分类目录
│   ├── 技术架构/
│   ├── 业务流程/
│   ├── 产品设计/
│   ├── 项目管理/
│   └── 通用知识/
├── _index/
│   ├── all-knowledge.json       # 全量索引
│   └── tag-index.json           # 标签倒排索引
└── _drafts/pending-review/      # 待审核知识点（通常忽略）
```

每个知识点是一个 Markdown 文件，包含 YAML Front Matter（id、title、category、tags、status 等）和结构化正文。

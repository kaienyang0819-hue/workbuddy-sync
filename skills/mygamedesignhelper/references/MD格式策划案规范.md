# MD 策划文档格式规范（AI 指令版）

> 本文档是 AI 将 Markdown 策划文档转换为 Excel 时的格式参考标准。
> AI 在生成或校验 MD 策划文档时，必须遵循以下所有规则。

---

## 1. 文档结构（强制顺序）

一份 MD 文件 = 一个项目 = 一个 Excel 文件。文档结构必须按以下顺序组织：

```
YAML frontmatter          ← 必须存在，文件最顶部
# 一级标题                 ← 仅一个，项目名称
## 系统A                   ← 可多个，每个生成一个 Excel Sheet
## 系统B
...
## 数据打点及tlog           ← 固定章节（关键词匹配）
## 数据统计需求              ← 固定章节（关键词匹配）
## 经验和教训                ← 固定章节（关键词匹配）
```

---

## 2. YAML Frontmatter

文件必须以 `---` 包围的 YAML 块开头。全部字段可选，缺失则在 Excel 中留空。

```yaml
---
title: 字符串              # 项目名称，建议必填
author: 字符串             # 撰写人
planner: 字符串            # 策划负责人
programmer: 字符串         # 程序负责人
artist: 字符串             # 美术负责人
created_date: YYYY-MM-DD   # 创建日期
status: 草案|正式发布|正在修改|注销  # 文档状态，默认"草案"
---
```

---

## 3. 标题层级规则

| MD 标记 | 语义 | Excel 映射 | 约束 |
|--------|------|-----------|------|
| `#` | 项目名称 | 文件名 + 文档维护Sheet标题 | 全文仅一个 |
| `##` | 系统名称 | 新建独立Sheet + `【系统名】`标题行 | 每个`##`创建新Sheet |
| `###` | 功能名称 | Sheet内功能标题（暗红底白字，B列） | 必须在`##`下 |
| `####` | 规则名称 | Sheet内规则标题（深灰底白字，C列） | 必须在`###`下 |
| `#####` | 规则细项 | Sheet内小标题（加粗黑字，D列） | 必须在`####`下 |

**约束**：
- `#` 全文仅出现一次
- 不得跳级使用（如 `##` 下直接出现 `####` 而无 `###`）
- 每个标题后必须空一行再写正文
- 正文/列表写在其所属标题的同级列中（`###`下的正文在B列，`####`下在C列，`#####`下在D列）

---

## 4. 正文内容格式

### 4.1 普通文本
直接书写，段落间用空行分隔。

### 4.2 重点标注
使用 `**加粗**` 语法。转换规则：
- 整行加粗 `**全部内容**` → Excel 中整行红色字体
- 行内加粗 `普通文字**重点**普通文字` → 红色与黑色混排

### 4.3 列表

**无序列表**：使用 `- ` 开头（半角减号+空格）
```
- 列表项A
- 列表项B
```

**子列表**：使用4个空格缩进
```
- 父级项
    - 子级项1
    - 子级项2
```

**有序列表**：使用 `数字. ` 格式
```
1. 步骤一
2. 步骤二
```

**禁止的列表格式**：
- ❌ `1、` `2、` `3、`（中文顿号）
- ❌ `（1）` `（2）`（中文括号）
- ❌ `a)` `b)` `c)`

### 4.4 表格

使用标准 Markdown 表格，三行结构：表头行 → 分隔行 → 数据行。

```
| 列名A | 列名B | 列名C |
|-------|-------|-------|
| 数据1 | 数据2 | 数据3 |
```

约束：
- 分隔行（`|---|`）必须存在，否则不会被识别为表格
- 表格前后必须有空行
- 表格会自动汇总到"数值表格设计"Sheet（完整版），系统Sheet中仅保留表头+3行简版

### 4.5 图片

三种情况：

| 情况 | 写法 | Excel 表现 |
|------|------|-----------|
| 已有图片文件 | `![描述](相对路径)` | 插入图片 |
| 预留图片位置 | `[图片占位: 描述文字]` | 灰色斜体 `[待插入图片: 描述文字]` |
| 无图片 | 不写 | 无处理 |

图片路径相对于 MD 文件所在目录。

## 5. 固定章节（关键词匹配）

以下 `##` 标题通过关键词匹配归入固定Sheet，不作为普通系统Sheet。

| 关键词（标题中包含任一即匹配） | 对应 Excel Sheet |
|---------------------------|----------------|
| `打点` / `tlog` / `埋点` | 数据打点及tlog |
| `数据统计` | 数据统计需求 |
| `经验` / `教训` | 经验和教训 |

### 5.1 数据打点及tlog

推荐使用表格格式，表头推荐列：

```
| 序号 | 所属模块 | 事件描述 | 优先级 | 接口ID/参数 | 负责人 |
```

可包含多个 `###` 子标题对表格分组（如"入口点击事件"、"资源变动事件"）。
若 MD 中无此章节，Excel 中自动生成空白模板。

### 5.2 数据统计需求

常规的 `###` → `####` → 正文/列表结构。

### 5.3 经验和教训

常规的 `###` → `####` → 正文/列表结构。

---

## 6. Excel 输出的 Sheet 顺序

```
1. 文档维护              ← 固定首位（目录 + 元信息 + 修订记录）
2. 系统Sheet A           ← 按 MD 中 ## 出现顺序
3. 系统Sheet B
...
N-3. 数值表格设计         ← 固定（自动汇总所有系统Sheet中的表格完整版）
N-2. 数据打点及tlog       ← 固定
N-1. 数据统计需求          ← 固定
N.   经验和教训            ← 固定末位
```

## 7. 完整模板

```markdown
---
title: {项目名称}
author: {撰写人}
planner: {策划负责人}
programmer: {程序负责人}
artist: {美术负责人}
created_date: {YYYY-MM-DD}
status: 草案
---

# {项目名称}

## {系统A名称}

### {功能A1名称}

#### {规则A1-1名称}

{规则说明正文}

- {列表项1}
- {列表项2}

**{需要重点标注的内容}**

| {列名1} | {列名2} | {列名3} |
|---------|---------|---------|
| {数据}  | {数据}  | {数据}  |

##### {规则细项标题}

- {细项内容}

#### {规则A1-2名称}

{正文...}

### {功能A2名称}

{正文...}

## {系统B名称}

{同上结构...}

## 数据打点及tlog

### {事件分类名称}

| 序号 | 所属模块 | 事件描述 | 优先级 | 接口ID/参数 | 负责人 |
|------|---------|---------|--------|-----------|--------|
| 1    | {模块}  | {描述}  | {P0/P1/P2} | {接口ID} | {人名} |

## 数据统计需求

### {指标分类}

#### {具体方向}

- {统计指标1}
- {统计指标2}

## 经验和教训

### 经验总结

#### {经验分类}

- {经验内容}

### 教训总结

#### {教训分类}

- {教训内容}
```

## 8. 校验清单

AI 在生成或校验 MD 文档时，按以下清单逐项检查：

- [ ] 文件以 `---` 开头的 YAML frontmatter 开始
- [ ] `title` 字段已填写
- [ ] 全文仅有一个 `#` 一级标题
- [ ] 每个 `##` 确实代表一个独立系统（非固定章节）
- [ ] 标题层级无跳级（`##` → `###` → `####` → `#####`）
- [ ] 所有标题后有空行
- [ ] 列表使用 `- ` 或 `1. ` 格式，无中文顿号/括号列表
- [ ] 表格有分隔行 `|---|`
- [ ] 重点内容使用 `**加粗**` 标注
- [ ] 图片使用 `![](路径)` 或 `[图片占位: 描述]`
- [ ] 包含"数据打点及tlog"章节（或标题含打点/tlog/埋点关键词）
- [ ] 包含"数据统计需求"章节（或标题含数据统计关键词）
- [ ] 包含"经验和教训"章节（或标题含经验/教训关键词）
- [ ] 固定章节位于所有系统章节之后
- [ ] 无内容遗漏——所有设计内容均已写入对应层级

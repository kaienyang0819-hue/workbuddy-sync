# MD → Excel 策划文档转换规范

> 版本: 1.0  
> 用途: 指导 AI 将 Markdown 格式的游戏策划文档转换为标准格式的 Excel (.xlsx) 策划文档  
> 原则: **内容完整性优先，格式可以适度降级但不允许丢失任何文本内容**

---

## 一、MD 文档写作规范

### 1.1 文档整体结构

一份 MD 策划文档对应**一个项目**，生成**一个 Excel 文件**。文档结构如下：

```markdown
---
title: 项目名称
author: 撰写人
planner: 策划负责人
programmer: 程序负责人
artist: 美术负责人
created_date: 2026-03-27
status: 草案
---

# 项目名称

## 系统A名称

### 功能A1名称

#### 规则A1-1名称

正文内容...

##### 规则细项

- 细项1
- 细项2

## 系统B名称

...

## 数据统计需求

...

## 经验和教训

...
```

### 1.2 层级映射规则

| MD 层级 | Excel 对应 | 列位置 | 说明 |
|---------|-----------|--------|------|
| YAML frontmatter | 文档维护 Sheet 元信息 | E-N列 | 撰写人、负责人、日期等 |
| `#` 一级标题 | Excel 文件名 + 文档维护 Sheet 标题 | A1 | 整个项目的名称 |
| `##` 二级标题 | **新建 Sheet** + **系统标题行** | B列 | 每个 `##` 对应一个独立的 Sheet，标题为 `【系统名】` |
| `###` 三级标题 | Sheet 内 **2级标题**（暗红底） | **B列** | 功能模块 |
| `####` 四级标题 | Sheet 内 **3级标题**（深灰底） | **C列** | 具体规则 |
| `#####` 五级标题 | 正文区域的**小标题**（加粗黑字） | **D列** | 规则细项标题 |
| 正文段落 | 正文内容 | **跟随上层标题** | 9号黑色字体，写在所属标题的同列 |
| 列表项 `- xxx` | 正文列表项 | **跟随上层标题** | 带圆点前缀 |

**正文列位置规则**：正文/列表/图片等内容块写在其上层标题所在的列。即功能(###)下的正文在B列，规则(####)下的正文在C列，规则细项(#####)下的正文在D列。

### 1.3 YAML Frontmatter 规范

文档必须以 YAML frontmatter 开头（用 `---` 包围）。所有字段均为可选，缺失则在 Excel 中留空。

```yaml
---
title: 项目名称          # 必填，项目名称
author: 张三             # 撰写人
planner: 李四            # 策划负责人
programmer: 王五         # 程序负责人
artist: 赵六             # 美术负责人
created_date: 2026-03-27 # 创建日期
status: 草案             # 文档状态：草案 / 正式发布 / 正在修改 / 注销
---
```

### 1.4 重点内容标注

使用 Markdown 加粗语法 `**内容**` 标注重点内容：

```markdown
角色等级达到30级后**必须完成转职任务**才能继续升级。
```

转换为 Excel 时，`**加粗**` 部分将使用**红色字体**区分于黑色正文。

### 1.5 图片处理

支持三种情况：

#### 已有图片

使用标准 Markdown 图片语法：

```markdown
![流程图描述](images/flow_chart.png)
```

转换时将尝试读取图片并插入 Excel。路径相对于 MD 文件所在目录。

#### 预留图片位置

使用自定义占位符标记：

```markdown
[图片占位: 战斗系统流程图]
```

转换时在 Excel 中写入灰色斜体占位文字：`[待插入图片: 战斗系统流程图]`

#### 无图片

不做任何处理。

### 1.6 表格

使用标准 Markdown 表格语法：

```markdown
| 等级 | 经验值 | 奖励 |
|------|--------|------|
| 1    | 100    | 金币x10 |
| 2    | 300    | 金币x30 |
```

转换时在 Excel 中按原始表格结构写入，表头行加粗。

### 1.7 特殊 Sheet 约定

以下 `##` 标题为**保留关键词**，不作为普通系统 Sheet，而是映射到固定的 Sheet：

| MD 标题 | Excel Sheet | 说明 |
|---------|-------------|------|
| `## 数据打点及tlog` | "数据打点及tlog" Sheet | 包含"打点"/"tlog"/"埋点"关键词 |
| `## 数据统计需求` | "数据统计需求" Sheet | 包含"数据统计"关键词 |
| `## 经验和教训` | "经验和教训" Sheet | 包含"经验"或"教训"关键词 |

另外，**"数值表格设计"Sheet** 为自动生成的固定Sheet，汇总所有系统Sheet中出现的表格完整版。

匹配规则：`##` 标题文本中包含对应关键词即可匹配。

### 1.8 tlog 打点章节写法

tlog 打点章节建议使用表格格式书写，表头推荐包含：序号、所属模块、事件描述、优先级、接口ID/参数、负责人。

```markdown
## 数据打点及tlog

### 入口点击事件

| 序号 | 所属模块 | 事件描述 | 优先级 | 接口ID/参数 | 负责人 |
|------|---------|---------|--------|-----------|--------|
| 1 | 宠物获取 | 商城购蛋按钮点击 | P0 | pet_buy_click | 张三 |
| 2 | 宠物获取 | 野外捕获按钮点击 | P0 | pet_catch_click | 张三 |

### 资源变动事件

| 序号 | 所属模块 | 事件描述 | 优先级 | 接口ID/参数 | 负责人 |
|------|---------|---------|--------|-----------|--------|
| 1 | 宠物获取 | 金币消耗-购蛋 | P0 | gold_cost_egg | 张三 |
```

### 1.9 内容书写建议

- 不要使用 `1、2、3……` 作为列表格式，请使用 Markdown 无序列表 `- ` 或有序列表 `1. `
- 分项下的分条，使用缩进列表（4空格缩进）
- 段落之间保留空行
- 标题后紧跟内容，不要留过多空行

## 二、Excel 输出格式标准

### 2.1 Sheet 结构

生成的 Excel 文件包含以下 Sheet（按顺序）：

```
1. 文档维护        ← 固定首个 Sheet
2. 系统A           ← 按 MD 中 ## 出现顺序
3. 系统B           ← ...
4. ...
N-3. 数值表格设计   ← 固定（汇总所有系统Sheet中的表格完整版）
N-2. 数据打点及tlog ← 固定
N-1. 数据统计需求   ← 固定
N.   经验和教训     ← 固定最后一个
```

### 2.2 全局格式设定

| 属性 | 值 |
|------|-----|
| 默认字体 | 微软雅黑 |
| A 列宽度 | 5.33（极窄，仅放 Sheet 标题时使用） |
| B 列宽度 | 50（系统标题 + 功能标题列） |
| C 列宽度 | 50（规则标题 + 规则内容列） |
| D 列宽度 | 50（规则细项标题 + 细项内容列） |
| 默认行高 | 自动 |
| 默认对齐 | 水平左对齐，垂直居中 |

### 2.3 颜色系统

| 元素 | 背景色 | 字体色 | 字号 | 加粗 | 说明 |
|------|--------|--------|------|------|------|
| Sheet 标题（行1-2） | `#404040` 深灰 | `#FFFFFF` 白色 | 20 | ✓ | 前2行整行合并 |
| 系统标题 `【xx】` | `#800000` 暗红 | `#FFFFFF` 白色 | 14 | ✓ | B列，行4，系统名称 |
| 2级标题（功能） | `#800000` 暗红 | `#FFFFFF` 白色 | 11 | ✓ | B列，对应 `###` |
| 3级标题（规则） | `#404040` 深灰 | `#FFFFFF` 白色 | 11 | ✓ | C列，对应 `####` |
| 5级小标题 | 无背景 | `#000000` 黑色 | 11 | ✓ | D列，对应 `#####` |
| 正文 | 无背景 | `#000000` 黑色 | 9 | ✗ | 普通段落 |
| **重点内容** | 无背景 | `#FF0000` 红色 | 9 | ✗ | MD 中 `**加粗**` 的内容 |
| 图片占位符 | 无背景 | `#999999` 灰色 | 9 | ✗ | 斜体 |
| 表格表头 | `#404040` 深灰 | `#FFFFFF` 白色 | 9 | ✓ | 加边框 |
| 表名标题 | 无背景 | `#000000` 黑色 | 11 | ✓ | 如"表1-xxx配置表" |
| 超链接 | 无背景 | `#0563C1` 蓝色 | 9 | ✗ | 带下划线 |
| 元信息标签 | `#F2F2F2` 浅灰 | `#000000` 黑色 | 11 | ✗ | 文档维护的字段标签 |
| 目录导航 | 无背景 | 链接色 | 11 | ✗ | 带下划线 |

### 2.4 文档维护 Sheet 详细布局

```
行1-2: [A1:XFD2 合并] "项目名称 设计文档"  → Sheet标题样式(深灰底+白字20号)

行4:   [B4] "内容概述"     (分类标题，深灰底+白字11号加粗)
       [E4] "文档维护"     (区域标题，暗红底+白字11号加粗)

行5:   [B5] → 目录项(带下划线超链接)
       [E5-F5] "撰写人"   (浅灰底+黑字，居中，边框)
       [G5-N5] "{值}"     (白底+黑字，居中，边框)

行6:   [B6] → 目录项
       [E6-F6] "策划负责人"
       [G6-N6] "{值}"

行7:   [B7] → 目录项
       [E7-F7] "程序负责人"
       [G7-N7] "{值}"

行8:   [B8] → 目录项
       [E8-F8] "美术负责人"
       [G8-N8] "{值}"

行9:   [B9] → 目录项(分类标题，深灰底)
       [E9-F9] "创建日期"
       [G9-N9] "{值}"

行10:  [B10] → 目录项
       [E10-F10] "文档状态"
       [G10-N10] "[√] 草案；[  ] 正式发布；[  ] 正在修改；[  ] 注销"

后续行: 左侧继续目录项，右侧为修订记录表
```

目录区域（B列）根据实际系统数量动态生成，每个系统名占一行，带超链接跳转到对应 Sheet。

目录分组结构：
- "内容概述"（深灰底分类标题）→ 下方是属于概述的系统Sheet链接
- "玩法流程"（深灰底分类标题）→ 下方是流程类Sheet链接
- "玩法内容"（深灰底分类标题）→ 下方是内容类Sheet链接
- "数据统计需求"（深灰底分类标题）
- "经验和教训"（深灰底分类标题）

> 简化处理：如果无法判断分类，所有系统Sheet名称按顺序列出即可，每个都生成超链接。

### 2.5 系统 Sheet 详细布局

```
行1-2: [A1:H2 合并] "系统名称"  → Sheet标题样式

行3:   (空行)

行4:   [B4] "【系统名称】"        → 系统标题样式(暗红底+白字14号加粗, B-D列涂色)
行5:   (空行)

行6:   [B6] "功能A名称"          → 2级标题样式(暗红底, B列)
行7:   (空行)
行8:   [C8] "规则A-1名称"        → 3级标题样式(深灰底, C列)
行9:   (空行)
行10:  [C10] 正文内容...          → 正文样式(9号黑字, 跟随规则在C列)
行11:  [C11] • 列表项1            → 正文样式，带圆点, C列
行12:  [C12] • 列表项2
行13:  (空行)
行14:  [D14] "规则细项标题"       → 5级小标题(加粗黑字11号, D列)
行15:  [D15] • 细项1              → 正文样式, D列
行16:  [D16] • 细项2
...
```

**层级→列映射**：
- `##` 系统标题 → B列（`【系统名】`格式，暗红底14号白字加粗）
- `###` 功能标题 → B列（暗红底11号白字加粗）
- 功能下正文/列表 → B列
- `####` 规则标题 → C列（深灰底11号白字加粗）
- 规则下正文/列表 → C列
- `#####` 规则细项标题 → D列（无背景11号黑字加粗）
- 规则细项下正文/列表 → D列

### 2.6 数值表格设计 Sheet 详细布局

此 Sheet 自动汇总所有系统 Sheet 中出现的 MD 表格的**完整版本**。

```
行1-2: [A1:J2 合并] "数值表格设计"  → Sheet标题样式

行4:   [B4] "【数值表格设计】"      → 系统标题样式(暗红底)

行6:   [B6] "表1-xxx（来源: 系统A）" → 表名标题(加粗黑字11号)
行7:   [B7-F7] 表头行               → 表头样式(深灰底白字9号加粗)
行8:   [B8-F8] 数据行               → 表格数据样式(边框)
...
行N:   [BN] "表2-yyy（来源: 系统B）" → 下一个表格
...
```

**系统 Sheet 中的表格处理**：
- 只保留**表头 + 最多3行示意数据**
- 表头行最后一列旁边加 `→ 查看完整表格` 超链接，跳转到"数值表格设计"Sheet 中的对应表格
- 如果数据超过3行，显示省略提示：`...（共N行，完整数据见'数值表格设计'Sheet）`

### 2.7 数据打点及tlog Sheet 详细布局

```
行1-2: [A1:G2 合并] "数据打点及tlog"  → Sheet标题样式

行4:   [B4] "【tlog及打点设计】"       → 系统标题样式(暗红底)

行6:   [B6] "入口点击事件"             → 表名标题(加粗黑字)
行7:   [B7-G7] 序号|所属模块|事件描述|优先级|接口ID/参数|负责人  → 表头
行8+:  数据行
...
```

如果 MD 中没有 tlog 章节，生成空白模板（表头 + 5行空白数据行）。

### 2.8 混合格式行处理（重点内容）

当一行文本中既有普通文本又有加粗重点时，使用 openpyxl 的 **Rich Text (InlineFont)** 功能实现同一单元格内的多色文字：

```
例: "角色等级达到30级后**必须完成转职任务**才能继续升级。"
→ 单元格内:
  "角色等级达到30级后" (黑色9号)
  "必须完成转职任务" (红色9号)
  "才能继续升级。" (黑色9号)
```

如果 Rich Text 实现过于复杂，降级方案：将重点文本单独占一行，整行红色。

### 2.9 表格处理

MD 表格在 Excel 中的处理分两种场景：

#### 系统 Sheet 中（简版）
- 从当前层级列开始，每列对应表格的一列
- 表头行：加粗 + 深灰底白字 + 边框
- 最多显示3行数据
- 表头行旁边加超链接跳转到"数值表格设计"Sheet
- 超过3行显示省略提示

#### 数值表格设计 Sheet 中（完整版）
- 从 B 列开始，表名标题在上
- 表头行：加粗 + 深灰底白字 + 边框
- 所有数据行完整显示
- 多个表格纵向排列，表间有空行

### 2.10 内容完整性保障

转换完成后需要输出内容完整性报告：

```
[转换报告]
MD 文档总行数: 230
MD 有效内容行数: 185 (排除空行和frontmatter)
Excel 总内容单元格数: 192
Sheet 数量: 5 (文档维护 + 战斗系统 + 成长系统 + 数据统计需求 + 经验和教训)
图片处理: 2 张已插入, 1 张占位符
警告: 无
```

## 三、转换流程

```
1. 读取 MD 文件
2. 解析 YAML frontmatter → DocumentMeta
3. 逐行扫描 → 识别标题层级、内容类型
4. 构建中间数据模型 (Document)
5. 收集所有表格，预计算锚点行号
6. 创建 Excel 工作簿
7. 生成"文档维护"Sheet (元信息 + 目录)
8. 按顺序生成各系统 Sheet（层级缩进, 表格简版+超链接）
9. 生成"数值表格设计"Sheet（汇总所有表格完整版）
10. 生成"数据打点及tlog"Sheet
11. 生成"数据统计需求"Sheet
12. 生成"经验和教训"Sheet
13. 处理图片插入
14. 保存 .xlsx 文件
15. 输出内容完整性报告
```

## 四、容错规则

| 场景 | 处理方式 |
|------|---------|
| frontmatter 缺失 | 不报错，元信息全部留空 |
| frontmatter 字段缺失 | 对应字段留空 |
| 无 `#` 一级标题 | 使用 frontmatter 的 title，都没有则用文件名 |
| 无 `##` 二级标题 | 所有内容放入一个名为"内容概述"的 Sheet |
| 标题层级跳跃（如 ## 直接到 ####） | 按实际层级处理，中间层级视为空 |
| 无法识别的 MD 语法 | 作为正文文本原样写入（不丢弃） |
| 图片文件不存在 | 写入占位文字 `[图片未找到: path]`，不报错 |
| 超长文本 | 单元格自动换行(wrap_text=True) |
| MD 中有 HTML 标签 | 去除标签，保留纯文本内容 |
| 空的 ## 章节 | 仍然创建 Sheet，内容区留空 |

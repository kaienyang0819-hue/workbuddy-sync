# 产品设计模板（Product Design Template）

八步链在产品功能设计场景的落地映射与产出结构。

## 八步 → 产品场景映射

| 步骤 | 产品场景含义 |
|---|---|
| 1 支柱 | 功能要解决的核心问题 + 不可动摇的产品原则 |
| 2 反支柱 | 明确不做（防范围蔓延、防方向漂移） |
| 3 目标排序 | 北极星指标 / 核心 KPI 排序 |
| 4 具体规则 | 功能规则、交互规则、业务规则 |
| 5 边界情况 | 异常流、极端场景、空/0/失败态 |
| 6 验收标准 | 可测的验收指标（行为 + 数据） |
| 7 需求拆解 | 可进 TAPD 的用户故事 + 验收要点 |
| 8 评审 | 需求评审：抓未定义的前置依赖 |

## 产品支柱的常见类型（供追问参考）

| 类型 | 例 | 想挡住什么 |
|---|---|---|
| 价值归属 | "价值必须落到用户可感知处" | 做了但用户无感 |
| 决策可逆 | "高风险操作可回退" | 一步错不可挽回 |
| 聚焦 | "只解决 X，不解决 Y" | 范围蔓延 |
| 张力 | "快 vs 稳"这类天然冲突 | 无原则的折中 |

## 产出结构：`<功能名>_设计定位.md`

```markdown
# <功能名> · 设计定位

## 一、定位
### 1. 支柱（3-5 条，含反支柱）
| 类型 | 支柱 | 想挡住什么 |
### 2. 目标排序
| 目标/指标 | 排序 | 来源支柱 |

## 二、设计
### 3. 具体规则
### 4. 边界情况
### 5. 数值/参数（初值，待验证）

## 三、验收与拆解
### 6. 验收标准
| 指标 | 标准 |
### 7. 需求拆解（可进 TAPD）
| 需求 | 用户故事 | 验收要点 |

## 四、评审
### 8. 自评审结论
> 通过 / 关注 / 驳回 + 理由（前置依赖、支柱违反、边界遗漏）
```

## 使用要点

1. **支柱最重**：第 1 步至少花一半精力，追问收敛（见 SKILL.md 第 5 节），不要急着写规则。
2. **规则每条回指支柱**：写第 3 步时，每条规则能标出"对应支柱几"，标不出的就是没想清楚的。
3. **评审抓前置依赖**：重点问"这个规则依赖的 X 定义了吗"，而不是"这个规则对不对"。
4. **产出落盘**：默认 `G:\project_output\`，用户有指定路径则用指定路径。

## 与 reqspec 的分工

- 本技能产出**定位**（方向、边界、验收、拆解），是"想清楚"
- reqspec 产出**需求规格**（用户故事规范、澄清歧义、六维审查），是"写规范"
- 顺序：本技能 → reqspec → 开发。用户只需定位时，走到本技能第 8 步即可，不必强行走 reqspec。

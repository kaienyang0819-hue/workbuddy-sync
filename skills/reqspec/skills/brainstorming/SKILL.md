# 头脑风暴

## 概述

通过**苏格拉底式对话**，帮助用户从模糊的想法中提炼出清晰的需求方向。输出是一份探索笔记，作为后续 `specifying` 技能的输入。

**核心原则：引导思考，而非替代思考。**

## 何时使用

- 用户说"我想做一个..."但描述很模糊
- 用户有多个想法，不确定哪个优先
- 用户对问题域不够了解，需要探索
- 用户说"帮我想想"、"头脑风暴一下"

## 何时不使用

- 用户已经有清晰的需求描述 → 直接使用 `specifying`
- 用户提供了完整的 PRD 或需求文档 → 直接使用 `reviewing`

## 流程

### 第一步：理解意图

向用户提出 **2-3 个开放式问题**，了解：

1. **动机**：为什么想做这个？解决什么问题？
2. **用户**：谁会使用它？他们现在怎么解决这个问题？
3. **边界**：最核心的一个功能是什么？什么明确不做？

<HARD-GATE>
- 每次最多问 3 个问题，不要一次性甩出 10 个问题轰炸用户
- 问题必须是开放式的（"你觉得..."而非"是不是..."）
- 在用户回答之前，不要自己脑补答案
</HARD-GATE>

### 第二步：提出方案框架

基于用户的回答，提出 **2-3 种不同的方案框架**：

```markdown
## 方案对比

| 维度 | 方案A：[名称] | 方案B：[名称] | 方案C：[名称] |
|------|-------------|-------------|-------------|
| 核心理念 | ... | ... | ... |
| 目标用户 | ... | ... | ... |
| 关键功能 | ... | ... | ... |
| 复杂度 | 低/中/高 | 低/中/高 | 低/中/高 |
| 适合场景 | ... | ... | ... |
```

每个方案用 **一句话** 总结其核心差异。

<HARD-GATE>
- 方案之间必须有实质性差异，不是换个名字
- 每个方案的描述不超过 5 句话
- 明确标注每个方案的取舍（得到什么、放弃什么）
</HARD-GATE>

### 第三步：深入选定方案

用户选择方案后（或要求混合多个方案），进入深入讨论：

1. **用户画像**：详细描述 1-2 个典型用户及其使用场景
2. **核心流程**：用自然语言描述用户的主要操作流程
3. **边界探索**：讨论边界情况和约束条件
4. **优先级**：区分 Must Have / Nice to Have / Out of Scope

### 第四步：生成探索笔记

将讨论结果整理为探索笔记，写入 `explorations/<name>.md`：

```markdown
# [功能名称] 探索笔记

## 创建日期
YYYY-MM-DD

## 背景与动机
[为什么要做这个？解决什么问题？]

## 目标用户
### 用户画像 1：[角色名]
- 背景：...
- 痛点：...
- 期望：...

### 用户画像 2：[角色名]（如有）
- 背景：...
- 痛点：...
- 期望：...

## 方案选择
### 考虑过的方案
[简要列出讨论过的方案及淘汰理由]

### 选定方案
[选定方案的核心描述]

## 核心功能设想
### Must Have（必须有）
1. ...
2. ...

### Nice to Have（最好有）
1. ...
2. ...

### Out of Scope（明确不做）
1. ...
2. ...

## 关键决策
| 决策 | 选择 | 理由 |
|------|------|------|
| ... | ... | ... |

## 开放问题
- [ ] ...
- [ ] ...

## 下一步
→ 使用 `specifying` 技能生成正式的需求规格说明书
```

### 第五步：请求审查

生成探索笔记后，使用以下提示模板请求一个**独立审查者**（子代理或独立对话）审查：

@spec-document-reviewer-prompt.md

<HARD-GATE>
- 审查者发现的 CRITICAL 级别问题必须解决后才能进入下一步
- HIGH 级别问题建议解决，由用户决定
- MEDIUM/LOW 可以带入 `specifying` 阶段再处理
</HARD-GATE>

## 常见错误

| 错误 | 正确做法 |
|------|---------|
| 一次问 10 个问题 | 每轮最多 3 个问题 |
| 替用户做决定 | 提出选项，让用户选择 |
| 过早讨论技术实现 | 只关注 WHAT 和 WHY，不关注 HOW |
| 探索笔记写成需求文档 | 探索笔记是自由形式的，需求文档由 `specifying` 生成 |
| 跳过方案对比 | 即使有明显的最优方案，也要给出对比供参考 |

## 完成标志

当以下条件满足时，头脑风暴阶段完成：

- [ ] 用户的核心动机已明确
- [ ] 目标用户已清晰
- [ ] 核心功能已达成共识
- [ ] 明确的 Out of Scope 边界
- [ ] 探索笔记已写入文件
- [ ] 审查已完成（至少无 CRITICAL 问题）

**下一步**：使用 `specifying` 技能，将探索笔记转化为正式的需求规格说明书。

# 澄清补全

## 概述

对已生成的需求规格说明书进行**多维度歧义扫描**，通过与用户的结构化对话，逐个消除模糊点和遗漏。

**核心原则：每次只问一个问题，每个答案立即写入文档。**

## 何时使用

- 需求文档中有 `[待澄清]` 标记
- 用户想检查需求是否有遗漏
- `reviewing` 报告指出有歧义需要解决

## 流程

### 第一步：加载并分析

1. 读取 `specs/<NNN>-<name>/requirements.md`
2. 按以下 **10 大分类法** 扫描文档中的歧义和遗漏

### 歧义扫描分类法

| 类别 | 扫描内容 |
|------|---------|
| **1. 功能范围** | 行为描述是否精确？是否有隐含但未明说的功能？ |
| **2. 数据模型** | 关键实体的属性是否完整？实体间关系是否清晰？ |
| **3. 用户交互** | 用户操作流程是否有跳跃？异常流程是否覆盖？ |
| **4. 非功能质量** | 性能指标是否可量化？安全要求是否具体？ |
| **5. 外部依赖** | 是否依赖第三方服务？依赖方的约束是否已知？ |
| **6. 边界情况** | 最大值/最小值/空值/并发等边界是否定义？ |
| **7. 约束与权衡** | 已知约束是否影响需求？是否有未暴露的权衡？ |
| **8. 术语一致性** | 同一概念是否有多个叫法？术语表是否完整？ |
| **9. 完成标准** | 验收场景是否可执行？成功标准是否可度量？ |
| **10. 优先级合理性** | P1 是否太多或太少？依赖关系是否影响优先级？ |

### 第二步：排列问题优先级

从扫描结果中选出**最多 5 个最高影响的问题**，按影响力排序。

<HARD-GATE>
问题排优先级的规则：

1. 影响多个用户故事的问题 > 影响单个的
2. 影响 P1 故事的问题 > 影响 P2/P3 的
3. 可能导致返工的问题 > 文字优化类的
4. 最多 5 个问题，整个会话最多 10 个
5. 不问投机性的技术问题（例如"你打算用什么数据库"）
</HARD-GATE>

### 第三步：逐个提问

**每次只向用户提一个问题**，格式如下：

```markdown
### 澄清问题 [1/N]

**类别**：[10大分类之一]
**相关需求**：[关联的用户故事或功能需求编号]

**问题**：[具体的问题]

**推荐选项**：

| 选项 | 描述 | 推荐理由 |
|------|------|---------|
| A ⭐ | [推荐选项] | [为什么推荐] |
| B | [替代选项] | [适用场景] |
| C | [替代选项] | [适用场景] |

> 你可以回复选项字母、回复"推荐"接受推荐项、或输入自定义答案。
```

<HARD-GATE>
提问铁律：

```
一次只问一个问题，等用户回答后再问下一个
```

| 禁止 | 允许 |
|------|------|
| 一次甩出 5 个问题 | 一次问 1 个，附带推荐选项 |
| "你考虑过X吗？Y呢？Z呢？" | "关于X，你倾向于A还是B？" |
| 开放式大问题"安全怎么考虑？" | 具体小问题"用户密码至少要求几位？" |
</HARD-GATE>

### 第四步：即时集成

每收到一个回答，**立即**更新需求文档：

1. **修改主文档**：将答案写入 `requirements.md` 的对应章节
2. **移除标记**：如果解决了 `[待澄清]` 项，删除该标记
3. **记录澄清**：在 `clarifications.md` 中追加记录

澄清记录格式：

```markdown
# 澄清记录

## 会话 YYYY-MM-DD

### 澄清 1
- **类别**：[分类]
- **问题**：[提出的问题]
- **决策**：[用户的选择或回答]
- **理由**：[为什么这么决策]
- **影响范围**：[修改了哪些需求]
```

<HARD-GATE>
```
每个答案必须立即写入文件，不要攒到最后一起写
```

理由：如果中途会话中断，已经澄清的内容不会丢失。这是原子操作原则。
</HARD-GATE>

### 第五步：尊重终止信号

用户随时可以终止澄清：

- 用户说"够了"、"先这样"、"下一步" → 立即停止提问
- 5 个问题问完 → 询问用户是否继续（"还有 N 个问题，要继续吗？"）
- 没有更多高影响问题 → 主动建议进入 `reviewing`

## 常见错误

| 错误 | 正确做法 |
|------|---------|
| 一次问多个问题 | 严格一次一个 |
| 问技术实现问题 | 只问业务和用户体验相关的 |
| 答案攒到最后写入 | 每个答案立即写入 |
| 问没有影响的小细节 | 只问高影响的关键问题 |
| 强迫用户回答所有问题 | 尊重用户的终止信号 |

## 合理化表

| AI 可能的借口 | 现实 |
|-------------|------|
| "还有很多问题没问完" | 5 个高质量问题胜过 20 个低质量问题 |
| "这个问题用户可能不了解" | 提供推荐选项，让用户有参考基础 |
| "先把所有问题列出来让用户选" | 列出来用户会选择性忽略，逐个问更有效 |

## 完成标志

- [ ] 所有 `[待澄清]` 标记已解决（或用户明确搁置）
- [ ] `clarifications.md` 已记录所有决策
- [ ] `requirements.md` 已同步更新
- [ ] 用户确认澄清阶段完成

**下一步**：使用 `reviewing` 技能进行质量审查。
